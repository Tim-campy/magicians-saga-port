# Town data, residents and selection

The town is SelectForm UI state backed by TownSystem records and resource archives, rather than the mission's ECS map. The S2 host runs native fresh Town data, Area reset/camera kernels, resident and hero initialization, and drawing through foreground and notice-stack flushing from extracted data. Persistent Update, its unlock-information script owner and the town-to-mission loop remain unbound.

## Overview

`SelectForm.Init` (`0x11e9c28`, 5644 bytes) retains MemberSystem at `+0x1b8` and TownSystem at `+0x1c0`. It owns a separate `townHuman_` list at `+0x1d0`. `_Draw` (`0x11f0714`, 10820 bytes) consumes TownSystem.GetBuildingList and DrawTownHuman, using the `select`, `resident` and `select_stage` archives. Reusing the mission's Map/Cell renderer would not implement this ownership model. Confidence high for these direct accesses/calls; complete rendering-provider semantics remain open.

The maintainer's extracted files are `textassets/20_select.bin`, `textassets/34_resident.bin` and `textassets/26_select_stage.bin`. These are local asset filenames, not ECS factory indices or inferred AppData resource IDs. Town table data comes from the indexed `xls` archive using the existing resource lookup profile.

## Behaviour

### Building list and cache

TownSystem owns an ordered list of `int32[3]` at `+0x20`, permission bytes at `+0x28` and a nullable cache at `+0x30`. A triple contains town index, building ID and value. The decoded normal-save integer slot19 supplies cache capacity. Fresh Init seeds the list from TownData.firstBuild for flag1 records and raises slot19 only when the flagged count is greater; it does not run ResetBuildingList. [Initialization](ecs-lifecycle.md#fresh-town-initialization) defines those gates and the forward-removal quirk of SetBuildingList.

GetBuildingList (`0x1169c44`, 452 bytes) returns an existing cache directly, without reading capacity or the source list. Otherwise it allocates and publishes a slot19-sized reference array before enumerating the source list. Each row must have at least three cells: read its signed town index, allocate a fresh three-int row, copy cells0..2, and store the copy at that index. Extra cells are ignored, gaps stay null and later duplicates overwrite earlier entries. The source row is not aliased. A late malformed row/index leaves the already-published partial cache available to the next call.

ResetBuildingList (`0x1169e08`, 604 bytes) clears `+0x30` before reading capacity, allocates an unpublished temporary projection and fills it with the same cloning/index rules. It then scans temporary slots in ascending order. For each null slot, read TownData at that index and call SetBuildingList(index, firstBuild, 0, true). This repairs source rows without recursively resetting the cache. The temporary array is never published and the cache remains null on success. Later failure retains earlier repairs. No entity creation, rendering or destruction occurs in this method. SelectForm.Init calls it at `0x11eaf88`.

### Resident ownership and remaining initialization

Each accepted resident receives a fresh zero-initialized `int32[11]`, with metadata indices ID, X, Y, VX, VY, SEB, DIR, MOVE, TYPE, FRAME and EX_VAL. Init supplies SEB38/direction2; VX/VY start zero. Living sub-members use the building position of their address, ordinary records can use town or area positions, and fallback placement consumes RNG. Appearance-rate Hits precedes a nonempty resident-term check. Successful rows consume Random60 and Random9999 after any position/lane draws. These observations establish the owner/data requirements, not a complete port of Init.

Decorations and clouds consume RNG before resident construction. A later Hits10 branch can change the first eligible row to type3 and draws the resident-present value even without an eligible row. Their draws cannot be silently omitted while claiming faithful resident initialization. The Chara projection retains both resource names, voice/town/area IDs, residentTerm and appearRate. Voice/bubble consumers remain separate from the initial human composition.

### Area state and camera

AreaData.NewGame calls virtual Find(true) when flags bit0 is set, then oldNewGame. The default Find overwrites discovery and is_new through BaseData.Find; a callback failure prevents all later reset work. oldNewGame replaces the three-row/six-int stage-detail array (`+0x20`), the three-row/two-int damage array (`+0x38`) and six-int area-detail array (`+0x28`), retaining the native allocation/publication order. It zeroes arrival-stage (`+0x30`), then rereads flags and writes bit0 to discovery (`+0x10`); is_new is not cleared by oldNewGame. Earlier array aliases retain their old storage. These resets do not serialize a save.

The background projection loads the full Area table, applies those kernels and supplies its discovery values to the existing SetActiveX/SetCameraPosition contracts. It does not infer discovery from filenames or choose a visible region from appearance. View dimensions, scale100, AppData view origin0/53 and the camera request0/-9999 are declared desktop context inputs; the native camera clamps that request. [Camera arithmetic](events.md#select-camera-limits-and-inertial-movement) defines the bounds and separate GameView/SelectForm dimensions.

The original texture color-space/atlas policy still needs runtime comparison.

### Scenery initialization and drawing

The selected Init cloud subsequence (`0x11ea1a4..0x11ea334`) clears the existing list and captures CLOUD14. Start x=-15; each test rereads form `+0x160` plus AppData.VIEW_W. The Init vector at ELF `0x626990`, stored at `0x11ea18c`, gives `+0x160=490`; VIEW_W is240. Each iteration reads raw GameView height, calls Lib.Random(0,height-170), calls AppData.Random(4), captures the destination list and appends a fresh eight-int row `[x,y,14,0,1,variant,0,20]`. Only after appending does AppData.Random(20) advance x, including zero spacing. There is no forced minimum increment.

InitDecoObject (`0x11eb52c`,488 bytes) publishes fresh separate bird/leaf lists before its first draw. AppData.Random(4) gives the bird count; every row comes from GenerateObjBird(false). AppData.Random(25)+5 then gives the leaf count; every row comes from GenerateLeaf(true). Appends retain the destination captured before generation; exceptions retain publications and earlier appends. ChangeState(0), between cloud initialization and InitDecoObject, selects soft-key text and writes state; it contains no RNG call. Earlier resource/form initialization and later resident construction are outside this selected subsequence.

Decoration rows are six int32 values `[id,x,y,frame,vx,vy]`. GenerateObjBird (`0x11f4ef8`,596 bytes) draws direction2, then id3 from AppData. Capture the selected left/right extent before offset60. A nonzero direction uses left-offset and speed3+1; zero uses right+offset and bitwise-complement speed3. An initial=true call additionally overwrites x with Lib.Random(left+50,right-50). Read raw height and draw y with Lib.Random(20,height-170), then AppData frame10 and vy3-1. Init deliberately passes false.

GenerateLeaf (`0x11f514c`,504 bytes) draws AppData id3 and Lib.Random(left,right). Read raw height twice, then consume Lib.Random(60). Compute baseY as wrapped `(wrap(height1*100)/-80)+height2`, with signed division truncated toward zero, and store baseY-offset. An initial=true call reads height a third time and overwrites y with Lib.Random(baseY,height3), retaining the earlier offset draw. Draw AppData frame10 and set vx/vy to0.

AppData and Lib own distinct JRandom instances; [RNG](rng.md#backend-initialization) defines that separation. AppData.Random returns0 without a draw for bound0, otherwise applies Abs after signed remainder. Lib.Random(bound) also skips bound0 but applies wrapping Abs before remainder; Lib.Random(min,max) always consumes a draw and matches the existing inclusive range kernel. The INT_MIN cases differ between bounded wrappers. The host uses two existing public seeded System.Random providers with explicit, provisional seeds at the cloud-subsequence entry; it does not claim the original global startup seed or prior stream position.

DrawDecoObject (`0x11f33f4`,800 bytes) supports type0 birds and type2 leaves. Capture camera+view origin; divide bird x-origin by20 with signed truncation. Enumerate the live list forward and cull each translated row with margins30/30. Negative vy sets Graphics.reverse=1. Capture the select resource and row position, then draw BIRD22 or LEAF23 at anchor2 using id as a **single SEB layer**, not a clip offset. Bird frames are direct; leaf frames divide by16. Reread vy after drawing and clear reverse only if it remains negative; an exception retains the preceding reverse mutation.

After type0 decoration drawing, `_Draw` at `0x11f0a80..0x11f0e10` executes two ground passes and clouds. Read GROUND4 frame0 bounds. First tile from left extent while below captured right+width, step width, with x=tile+capturedOriginX/2; cull at SelectHeight-1 with margin width+5, then draw BG0 frame3 at capturedOriginY-125+freshRawHeight. Read GROUND4 bounds again and raw height, capture fixed y=rawHeight-boundsHeight+capturedOriginY, and tile GROUND4 frame1 with full originX. Finally visit clouds backward, cull x=row.x+originX/20 at SelectHeight-1 with margin80, and draw each row's clip/frame at that x and row.y+originY. These passes reuse the existing culling, bounds, bitmap and mesh contracts.

### Floor strips and gate

The next `_Draw` segment (`0x11f0e10..0x11f0fe0`) captures start=leftExtent+40 and end=rightExtent-72. Iterate tile positions below end with wrapped step32. Each iteration queries SelectHeight and culls `(originX+tile,SelectHeight-1)` with margins74/0, then computes next=tile+32. A visible strip uses frame0 at start and frame1 otherwise; frame2 overrides either when next>end. Equality retains the first/middle choice. Read raw GameView height, capture the current FLOOR2 Seb and SELECT_FLOOR image3, then draw at `(originX+tile,originY-100+height)`. Culling suppresses these resource/height queries. Captured extents and origin remain fixed across callbacks.

AppData.DrawSeb (`0x11041a4`,224 bytes) ignores its AppData receiver. Require the supplied Seb, call instance GetSprites with the raw frame (no max-frame remainder), retain that returned array and iterate forward using its live length. Null rows fail; TexId<0 skips remaining fields. A nonnegative TexId requires eight cells and nonnull Graphics, then wraps supplied x/y plus offsets6/7 before binary32 conversion. DrawImage uses the supplied Image and UV/size cells2..5, regardless of TexId. Null Image is forwarded to Graphics. The helper adds no sprite reversal, blend/color, anchor, image motion or clock side effects. It reuses the existing instance evaluator and image-draw service.

After the strips, including an empty/fully culled loop, call Graphics.PushFont(10), leaving bitmap depth unchanged. Read raw height, capture the select resource, require it before reading GATE3, and draw explicit frame0/layer0 at `(originX+40,originY-70+height)`. This gate is not culled here. ResourceManager.DrawSeb (`0x1ba8694`,84 bytes) takes the signed frame remainder, then forwards the selected layer without anchoring. Anchor0 is not a substitute: an anchored call would subtract the frame's bounding origin. Building-cache reads begin at `0x11f0fe4`.

### Building records and reward availability

BuildingData.Load (`0x116cca8`,280 bytes) stores ten tokens in order: int32 ID, name, resource name, int32 image, owner ID, type, cost, base-have, explanation, flags. Native offsets are ID+0x18, flags+0x1c, name+0x28, resource+0x30, image+0x38, owner+0x3c, type+0x40, cost+0x44, base-have+0x48 and explanation+0x50. Null/empty text leaves the receiver unchanged; a late parse failure retains earlier stores. Saved have/discovery are separate. IsDecoration (`0x116c9f0`,32 bytes) accepts only types8/12.

KingRewardData.Load (`0x1171c70`,232 bytes) reads ID, name, int32 score threshold, crystal level, timing and two framed int[][] scripts. It does not modify received+0x48. NewGame (`0x1171d64`,8 bytes) clears only that byte. The read-only CheckExeKingEvent(false) branch (`0x11169c4`) captures system high score once, narrows its int64 value to signed low32 and scans reward rows in order. The first unreceived row whose threshold is at most that score returns true; no reward or event executes. Catalog owners, lengths, received bytes and thresholds are reread at the native call boundaries. The granting/true branch remains unported.

The initial cache has building12/image47/type8 and building4/image14/type7, followed by two disabled empty slots. Character NewGame sets living address to -1; the occupancy projection retains only records with flags&4 and address!=-1, indexes by address and lets later duplicates overwrite. This derives fresh empty occupancy from Chara resets without initializing Member ECS or skipping resident RNG while claiming complete SelectForm.Init.

Unselected slots request control10 rectangle(x-40,y-70,80,90), flags(slot|0x220000), padding(-10,-10,-10,-10). PopFont ends font7 before the area pass.

DrawSebStack stores fresh int32[7] rows `[resource,x,y,clip,frame,layer,depth]`; default depth -99999 becomes the pre-append list count. ### Resident initialization

The resident subsection of Init (`0x11ea550..0x11eaf78`) captures total quest challenges and the persisted STORE_KAIRO_LIMIT, then publishes a fresh destination list. It filters Chara flags0x20 in table order. `Lib.Shuffle(source,null)` (shared generic body `0x12d5248`,1024 bytes) copies source into a new Vector, runs Fisher-Yates with Lib.Random(n) for n=N down to2, and returns that destination. Init discards the return at `0x11ea6e8`: source order survives while the Lib stream consumes N-1 draws. This observable quirk is retained without reconstructing public Vector/LINQ internals.

Append nonnull living submembers in ascending address order. With at most8 such members, form the ordered recruited!=0/living==-1 candidate list and append one AppData.Random(count) choice when nonempty. Duplicated candidates remain duplicated until later position filtering. Fresh Chara NewGame clears recruit/living, deriving an empty optional-visitor set without an omitted RNG call. Capture GetActiveX once before processing candidates.

For every candidate consume Lib.Random(100) and compare it with appearRate, even for rates outside0..100. Only a passing appearance check reads residentTerm; null/empty terms bypass condition evaluation, while nonempty terms use the existing ordered event-condition evaluator. A living submember takes its building position and dedup key100+address. A submember without residence takes building0.x+45 without a key. Other records prefer townId (key=townId), then areaId (key=1000+areaId), otherwise consume AppData.Random(3) for a fallback lane and retain x=-1. Claim dedup keys before suppressing flag0x80 records whose captured challenges equal the store limit. Such a suppressed row can block a later candidate at the same key; its fallback lane draw has already happened.

For an accepted row capture the destination owner and allocate a zero int32[11]. Write ID; resolve x==-1 with AppData.Random(activeRange[1]); write X/lane, SEB38, DIR2, MOVE=!Check64 and TYPE=Check128. Store records force lane0. Consume AppData.Random(60), reread Check64 and add60 when set; consume AppData.Random(9999), then append to the captured owner. Every arithmetic operation wraps32. After all candidates consume Lib.Hits(10). On success change the first x>=1/type0 row to type3; even without an eligible row, consume Lib.Random(2,5)*100 and write the present value.

GetBuildingPos (`0x11eb8f4`,156 bytes) returns `(90*index+130,rawHeight-100)`. GetPosObstacle (`0x11f4088`,244 bytes) captures camera/view origins, writes X=cameraX+VIEW_X+rightExtent-120, queries raw height, then writes Y=cameraY+VIEW_Y+height-70. GetActiveX (`0x11eb714`,480 bytes) starts at[leftExtent+60,rightExtent-60]. If capacity<TownData.Length, replace the right value with obstacleX-captured(cameraX+VIEW_X)-30, retaining the obstacle helper's otherwise unused height query. ### Hero and target indicator

Init stores currentX40.0, direction1 and targetX40.0 at form offsets `+0x124/+0x128/+0x164`; counter `+0xd0` is zero. These are native defaults, not selected scenario values. The hero pass captures target/current, selects idle clip36 when equal or walking clip40 otherwise, then queries raw height.
