# Town data, residents and selection

The town is SelectForm UI state backed by TownSystem records and resource archives, rather than the mission's ECS map. The S2 host runs native fresh Town data, Area reset/camera kernels and selected SelectForm scenery/building/area drawing from extracted data. Resident/foreground drawing, notice-stack flushing and the town-to-mission loop remain unbound.

## Overview

`SelectForm.Init` (`0x11e9c28`, 5644 bytes) retains MemberSystem at `+0x1b8` and TownSystem at `+0x1c0`. It owns a separate `townHuman_` list at `+0x1d0`. `_Draw` (`0x11f0714`, 10820 bytes) consumes TownSystem.GetBuildingList and DrawTownHuman, using the `select`, `resident` and `select_stage` archives. Reusing the mission's Map/Cell renderer would not implement this ownership model. Confidence high for these direct accesses/calls; complete rendering-provider semantics remain open.

The maintainer's extracted files are `textassets/20_select.bin`, `textassets/34_resident.bin` and `textassets/26_select_stage.bin`. These are local asset filenames, not ECS factory indices or inferred AppData resource IDs. Town table data comes from the indexed `xls` archive using the existing resource lookup profile.

## Behaviour

### Building list and cache

TownSystem owns an ordered list of `int32[3]` at `+0x20`, permission bytes at `+0x28` and a nullable cache at `+0x30`. A triple contains town index, building ID and value. The decoded normal-save integer slot19 supplies cache capacity. Fresh Init seeds the list from TownData.firstBuild for flag1 records and raises slot19 only when the flagged count is greater; it does not run ResetBuildingList. [Initialization](ecs-lifecycle.md#fresh-town-initialization) defines those gates and the forward-removal quirk of SetBuildingList.

GetBuildingList (`0x1169c44`, 452 bytes) returns an existing cache directly, without reading capacity or the source list. Otherwise it allocates and publishes a slot19-sized reference array before enumerating the source list. Each row must have at least three cells: read its signed town index, allocate a fresh three-int row, copy cells0..2, and store the copy at that index. Extra cells are ignored, gaps stay null and later duplicates overwrite earlier entries. The source row is not aliased. A late malformed row/index leaves the already-published partial cache available to the next call.

ResetBuildingList (`0x1169e08`, 604 bytes) clears `+0x30` before reading capacity, allocates an unpublished temporary projection and fills it with the same cloning/index rules. It then scans temporary slots in ascending order. For each null slot, read TownData at that index and call SetBuildingList(index, firstBuild, 0, true). This repairs source rows without recursively resetting the cache. The temporary array is never published and the cache remains null on success. Later failure retains earlier repairs. No entity creation, rendering or destruction occurs in this method. SelectForm.Init calls it at `0x11eaf88`.

### Resident ownership and remaining initialization

Each accepted resident receives a fresh zero-initialized `int32[11]`, with metadata indices ID, X, Y, VX, VY, SEB, DIR, MOVE, TYPE, FRAME and EX_VAL. Init supplies SEB38/direction2; VX/VY start zero. Living sub-members use the building position of their address, ordinary records can use town or area positions, and fallback placement consumes RNG. Appearance-rate Hits precedes a nonempty resident-term check. Successful rows consume Random60 and Random9999 after any position/lane draws. These observations establish the owner/data requirements, not a complete port of Init.

Decorations and clouds consume RNG before resident construction. A later Hits10 branch can change the first eligible row to type3 and draws the resident-present value even without an eligible row. Their draws cannot be silently omitted while claiming faithful resident initialization. The current combat Chara projection discards resource, voice, town, area, residentTerm and appearRate fields; these and Building/Voice records must reach the town provider before those consumers execute.

### Area state and camera

AreaData.NewGame calls virtual Find(true) when flags bit0 is set, then oldNewGame. The default Find overwrites discovery and is_new through BaseData.Find; a callback failure prevents all later reset work. oldNewGame replaces the three-row/six-int stage-detail array (`+0x20`), the three-row/two-int damage array (`+0x38`) and six-int area-detail array (`+0x28`), retaining the native allocation/publication order. It zeroes arrival-stage (`+0x30`), then rereads flags and writes bit0 to discovery (`+0x10`); is_new is not cleared by oldNewGame. Earlier array aliases retain their old storage. These resets do not serialize a save.

The background projection loads the full Area table, applies those kernels and supplies its discovery values to the existing SetActiveX/SetCameraPosition contracts. It does not infer discovery from filenames or choose a visible region from appearance. View dimensions, scale100, AppData view origin0/53 and the camera request0/-9999 are declared desktop context inputs; the native camera clamps that request. [Camera arithmetic](events.md#select-camera-limits-and-inertial-movement) defines the bounds and separate GameView/SelectForm dimensions.

### Initial drawing prefix

`draw_select_background` implements `_Draw` at `0x11f0850..0x11f0a6c`, ending before DrawDecoObject(type0). It does not stand in for the complete form. The earlier ResetTouchList/IsTopForm calls and all later decoration, construction, resident, cloud, marker and menu work remain outside this selected segment.

Read resSelect.images[RESSELECT_IMG_BG].GetPixel(0,0); multiply RGB by binary32 255, convert with ARM64 FCVTZS semantics and pass alpha255 to Color. Fill `(0,0,SelectWidth,SelectHeight)`. Capture baseY as wrapped cameraY+VIEW_Y. Start tileX at the captured left extent; before each test reread the right extent and resSelect. While tileX is smaller, query raw GameView height, require the captured resource, read the live background clip and draw frame0 at `(tileX, baseY-125+viewHeight)`, then wrap-add240. The final false test still refreshes resSelect. Draw frame1 using fresh signed cameraX/30 truncated toward zero, plus30, and captured baseY+20. These are explicit frames, not the resource's current clock frame. Resource-null failures preserve the native height/clip access prefixes.

The background selectors are established constants for this APK, not provisional guesses: RESOURCE[1][11] is `select`; RESSELECT_SEB_BG static `+0x164` is0 and RESSELECT_IMG_BG static `+0x1e0` is9. Native GetPixel flips the texture's bottom-up Y using height-y-1; decoded top-down RGBA sampling uses its top-left pixel. The original texture color-space/atlas policy still needs runtime comparison.

### Scenery initialization and drawing

The selected Init cloud subsequence (`0x11ea1a4..0x11ea334`) clears the existing list and captures CLOUD14. Start x=-15; each test rereads form `+0x160` plus AppData.VIEW_W. The Init vector at ELF `0x626990`, stored at `0x11ea18c`, gives `+0x160=490`; VIEW_W is240. Each iteration reads raw GameView height, calls Lib.Random(0,height-170), calls AppData.Random(4), captures the destination list and appends a fresh eight-int row `[x,y,14,0,1,variant,0,20]`. Only after appending does AppData.Random(20) advance x, including zero spacing. There is no forced minimum increment.

InitDecoObject (`0x11eb52c`,488 bytes) publishes fresh separate bird/leaf lists before its first draw. AppData.Random(4) gives the bird count; every row comes from GenerateObjBird(false). AppData.Random(25)+5 then gives the leaf count; every row comes from GenerateLeaf(true). Appends retain the destination captured before generation; exceptions retain publications and earlier appends. ChangeState(0), between cloud initialization and InitDecoObject, selects soft-key text and writes state; it contains no RNG call. Earlier resource/form initialization and later resident construction are outside this selected subsequence.

Decoration rows are six int32 values `[id,x,y,frame,vx,vy]`. GenerateObjBird (`0x11f4ef8`,596 bytes) draws direction2, then id3 from AppData. Capture the selected left/right extent before offset60. A nonzero direction uses left-offset and speed3+1; zero uses right+offset and bitwise-complement speed3. An initial=true call additionally overwrites x with Lib.Random(left+50,right-50). Read raw height and draw y with Lib.Random(20,height-170), then AppData frame10 and vy3-1. Init deliberately passes false.

GenerateLeaf (`0x11f514c`,504 bytes) draws AppData id3 and Lib.Random(left,right). Read raw height twice, then consume Lib.Random(60). Compute baseY as wrapped `(wrap(height1*100)/-80)+height2`, with signed division truncated toward zero, and store baseY-offset. An initial=true call reads height a third time and overwrites y with Lib.Random(baseY,height3), retaining the earlier offset draw. Draw AppData frame10 and set vx/vy to0.

AppData and Lib own distinct JRandom instances; [RNG](rng.md#backend-initialization) defines that separation. AppData.Random returns0 without a draw for bound0, otherwise applies Abs after signed remainder. Lib.Random(bound) also skips bound0 but applies wrapping Abs before remainder; Lib.Random(min,max) always consumes a draw and matches the existing inclusive range kernel. The INT_MIN cases differ between bounded wrappers. The host uses two existing public seeded System.Random providers with explicit, provisional seeds at the cloud-subsequence entry; it does not claim the original global startup seed or prior stream position.

DrawDecoObject (`0x11f33f4`,800 bytes) supports type0 birds and type2 leaves. Capture camera+view origin; divide bird x-origin by20 with signed truncation. Enumerate the live list forward and cull each translated row with margins30/30. Negative vy sets Graphics.reverse=1. Capture the select resource and row position, then draw BIRD22 or LEAF23 at anchor2 using id as a **single SEB layer**, not a clip offset. Bird frames are direct; leaf frames divide by16. Reread vy after drawing and clear reverse only if it remains negative; an exception retains the preceding reverse mutation.

After type0 decoration drawing, `_Draw` at `0x11f0a80..0x11f0e10` executes two ground passes and clouds. Read GROUND4 frame0 bounds. First tile from left extent while below captured right+width, step width, with x=tile+capturedOriginX/2; cull at SelectHeight-1 with margin width+5, then draw BG0 frame3 at capturedOriginY-125+freshRawHeight. Read GROUND4 bounds again and raw height, capture fixed y=rawHeight-boundsHeight+capturedOriginY, and tile GROUND4 frame1 with full originX. Finally visit clouds backward, cull x=row.x+originX/20 at SelectHeight-1 with margin80, and draw each row's clip/frame at that x and row.y+originY. These passes reuse the existing culling, bounds, bitmap and mesh contracts.

### Floor strips and gate

The next `_Draw` segment (`0x11f0e10..0x11f0fe0`) captures start=leftExtent+40 and end=rightExtent-72. Iterate tile positions below end with wrapped step32. Each iteration queries SelectHeight and culls `(originX+tile,SelectHeight-1)` with margins74/0, then computes next=tile+32. A visible strip uses frame0 at start and frame1 otherwise; frame2 overrides either when next>end. Equality retains the first/middle choice. Read raw GameView height, capture the current FLOOR2 Seb and SELECT_FLOOR image3, then draw at `(originX+tile,originY-100+height)`. Culling suppresses these resource/height queries. Captured extents and origin remain fixed across callbacks.

AppData.DrawSeb (`0x11041a4`,224 bytes) ignores its AppData receiver. Require the supplied Seb, call instance GetSprites with the raw frame (no max-frame remainder), retain that returned array and iterate forward using its live length. Null rows fail; TexId<0 skips remaining fields. A nonnegative TexId requires eight cells and nonnull Graphics, then wraps supplied x/y plus offsets6/7 before binary32 conversion. DrawImage uses the supplied Image and UV/size cells2..5, regardless of TexId. Null Image is forwarded to Graphics. The helper adds no sprite reversal, blend/color, anchor, image motion or clock side effects. It reuses the existing instance evaluator and image-draw service.

After the strips, including an empty/fully culled loop, call Graphics.PushFont(10), leaving bitmap depth unchanged. Read raw height, capture the select resource, require it before reading GATE3, and draw explicit frame0/layer0 at `(originX+40,originY-70+height)`. This gate is not culled here. ResourceManager.DrawSeb (`0x1ba8694`,84 bytes) takes the signed frame remainder, then forwards the selected layer without anchoring. Anchor0 is not a substitute: an anchored call would subtract the frame's bounding origin. Building-cache reads begin at `0x11f0fe4`.

### Building records and reward availability

BuildingData.Load (`0x116cca8`,280 bytes) stores ten tokens in order: int32 ID, name, resource name, int32 image, owner ID, type, cost, base-have, explanation, flags. Native offsets are ID+0x18, flags+0x1c, name+0x28, resource+0x30, image+0x38, owner+0x3c, type+0x40, cost+0x44, base-have+0x48 and explanation+0x50. Null/empty text leaves the receiver unchanged; a late parse failure retains earlier stores. Saved have/discovery are separate. IsDecoration (`0x116c9f0`,32 bytes) accepts only types8/12.

KingRewardData.Load (`0x1171c70`,232 bytes) reads ID, name, int32 score threshold, crystal level, timing and two framed int[][] scripts. It does not modify received+0x48. NewGame (`0x1171d64`,8 bytes) clears only that byte. The read-only CheckExeKingEvent(false) branch (`0x11169c4`) captures system high score once, narrows its int64 value to signed low32 and scans reward rows in order. The first unreceived row whose threshold is at most that score returns true; no reward or event executes. Catalog owners, lengths, received bytes and thresholds are reread at the native call boundaries. The granting/true branch remains unported.

The initial cache has building12/image47/type8 and building4/image14/type7, followed by two disabled empty slots. Character NewGame sets living address to -1; the occupancy projection retains only records with flags&4 and address!=-1, indexes by address and lets later duplicates overwrite. This derives fresh empty occupancy from Chara resets without initializing Member ECS or skipping resident RNG while claiming complete SelectForm.Init.

### Building drawing prefix

`draw_select_town_buildings` covers `_Draw` at `0x11f0fe4..0x11f1d98`. Capture normal-save slot19 and the cache once. For each slot query raw height, cull at `(originX+130+90*i,SelectHeight-1)` with margins60/0, and draw a nonnull row's CHIP1 underlay at `(originX+85+90*i,originY-100+rawHeight)`. Texture17 is used when i%3==0, otherwise18. PopFont removes the preceding font10; PushFont(7) begins the building scope. Occupancy is captured even for zero capacity.

The second loop queries GetBuildingPos raw height before culling. Existing IDs draw CHIP1 with explicit Building.image and the captured counter+ID. Empty slots use image33 when permission bit0 is set, otherwise32, and reload the counter after resource callbacks. Calls use scale100/anchor17 and all SEB layers. The shared DrawSebImg adapter evaluates SEB rows before selecting an override image, uses that image's motion dictionary and preserves retained-coordinate changes between layers; layer selection does not bypass evaluation of the other rows.

Non-decoration buildings queue BOARD11/frame1 at y-80 and request their actual name at y-79, anchor34/font7, only for the top form. An unselected label scope uses render mode(0,160,0); its cleanup rereads selection. Type7 queues ARROW17 at y-45 when the read-only reward query succeeds; type6 does so for an empty residence. Enabled empty slots queue the arrow at y-50. Type12's first-share indicator requires system share-count0, form state0 and ShareActive. MyConfig cctor (`0x11743f8`) initializes ShareActive=false; an unbound share-count read fails instead of inventing persisted state.

The late interaction path reads ShareActive even for vacant slots. Type8 is never interactive; type12 is skipped when sharing is inactive. Selected enabled slots queue BUTTON_GO9 at(x-5,y+14), frame(counter/6)%maxFrame, and request control4 rectangle(x-40,y-90,80,90), flags27, padding(-10,-10,-10,25). Unselected slots request control10 rectangle(x-40,y-70,80,90), flags(slot|0x220000), padding(-10,-10,-10,-10). PopFont ends font7 before the area pass.

DrawSebStack stores fresh int32[7] rows `[resource,x,y,clip,frame,layer,depth]`; default depth -99999 becomes the pre-append list count. Requests remain queued until the later native flush after area/resident drawing. Rendering them immediately would change overlap order. Glyph output and interactive hit registration are presentation-service stubs; queueing, game decisions and sprite drawing execute.

### Area drawing prefix

`draw_select_town_areas` implements `_Draw` at `0x11f1d9c..0x11f2324`. It queries and discards raw GameView height, then pushes font10. Each iteration captures the area catalog for both its length and row lookup. GetAreaPos (`0x11eb990`,156 bytes) queries raw height before returning wrapped `(-160-129*index,rawHeight-157)`. Cull `(originX+positionX,SelectHeight-1)` with margins134/0. After culling, reread the catalog/row for discovery==1; the earlier captured row supplies image/name even if a callback replaces the catalog.

A found area draws resBg (RESOURCE ordinal0, AppData+0xd0), explicit clip3/frameArea.image, at(x+18,y-23). This bypasses GetResourceManager, whose established selector set does not include0. Enqueue select11/AREA_NAME10 at(x+64,y-5), frame1 for selected area and0 otherwise. A selected area also queues GO9 at(x+64,y+72), frame(counter/6)%maxFrame, and requests control4 rectangle(x+50,y+45,29,37), flags28, padding(15,15,50,5). An unselected found area requests control29 rectangle(x,y,129,82), flags(index|0xc0000), same padding. Selection is captured before the name-clip query; animated notices resolve selector/maxFrame before reading the live counter.

SetColor uses AppData static+0x3b0; the top-form snapshot gates the actual name request at(x+64,y+1), anchor34/font10. It does not gate area-mark processing. When areaMark[index]==1, queue common2/clip15 at(x+50,y-24), frame(counter/4)%maxFrame, then select11/ARROW17 at(x+64,y-28), framecounter%maxFrame. Other mark values queue neither. Init allocates a fresh zero int32[areaCount] at `0x11ea520..0x11ea548`; the existing marker refresh writes1/2 only after Update becomes reachable.

GetAreaNum (`0x111511c`,212 bytes) starts at-1 and increments for every row whose discovery equals1, refreshing catalog length and row sources at each native boundary. Null rows fail; gaps are not skipped. It counts found rows rather than returning their largest index. For an unfound area, query it once and skip if wrapped(result+1)>current catalog length; query it again and draw only index==wrapped(result+1). That slot draws resSelect/FENCE12 at(x,y), using the clip's current frame, not the form counter. Only its touch request requires form state0: control29, rectangle129x82, flags(index|0xc0000), padding(5,5,20,5).

The current-frame overload calls Seb.PushThisFrameRender (`0x1bb3790`) before reading the clock. The supported explicit `--automatic-images 0` context follows its early false/no-mutation branch; the true registration/automatic-clock lifecycle remains unbound and is rejected. There is no PushClip in `_Draw`; PopClip at `0x11f2334` releases an inherited caller scope. This host stops before that call and before resident lane0. Font10 and the notice queue remain active at the boundary.

### Resident composition and notice flushing

DrawTownHuman (`0x11f38a8`) captures origin(cameraX+VIEW_X,cameraY+VIEW_Y-92) and IsTopForm, then materializes rows filtered by lane `row[2]` in their original order. The predicate (`0x1207434`,52 bytes) requires a nonnull row with at least three cells. It does not test resident type `row[8]`. Each accepted row queries raw height and culls `(originX+row[1],SelectHeight-1)` with margins60/0. Its drawing position is `(originX+row[1],baseY+rawHeight+9*row[2])`; the human call uses characterID=row0, clip=row5, frame=row9 and scale100.

AppData.DrawScaledHuman (`0x110de38`,36 bytes) forwards to the896-byte overload at `0x110de5c` with an additional zero argument. That composition is unported. Native resident initialization also needs the retained Chara resource names, town/area IDs, appearance rate and resident-term scripts; no artificial resident roster substitutes for those inputs. Fresh Chara.NewGame gives recruit0/living-1, making the optional recruited/not-living candidate set empty without an RNG draw. The initial resident filter is Chara.Check(0x20), then living submembers are appended. Per-candidate Lib.Hits(appearRate) precedes nonempty residentTerm evaluation. The persisted store-limit value is a separate required input before flag0x80 residents can be faithfully initialized.

The parent draws resident lane0 at `0x11f2344`, hero at `0x11f2528`, lanes1/2 at `0x11f2538/0x11f2548`, leaves at `0x11f2fb4` and only tail-calls StackListDraw at `0x11f3144`. StackListDraw (`0x11f417c`,624 bytes) enumerates the captured queue in insertion order, culls row1/2 with margins60/0, resolves resource=row0 and draws clip/frame/layer=row3..5. It does not read row6 or sort by that cell. Normal completion disposes the enumerator and clears the current form's queue; a failure disposes/rethrows without clearing. Early flushing before those layers would change overlap and failure behavior.

### Quest selection boundary

The area action stores normal-save slot8. SelectStageForm enumerates the selected Area.stages and filters by quest discovery; confirmation stores QuestData.id in slot9. SelectStageForm.Update checks/consumes stamina and waits41 production-state updates before changing to QuestForm. Its stamina comparison lies at `0x1208084..0x1208094`, and the UseStamina call is at `0x1208150`. StartExplore separately establishes the selected records and exploration ledger. These are separate from the S1 CLI's explicit quest scenario. The existing selection kernels and evidence are described in [mission selection](integration.md#native-mission-selection-and-area-records-s1-a1).

## Port

`get_town_buildings` and `reset_town_buildings` live beside the Init/SetBuildingList kernels in [pass_initialization.cpp](../../src/core/gameplay/pass_initialization.cpp). Their cache reference represents native `+0x30` separately from the existing initialization state. [Contract tests](../../tests/test_pass_initialization.cpp) cover aliases, clones, duplicates, gaps, negative/out-of-range inputs, publication/failure prefixes and deferred repair order. Existing standard containers implement the storage operations; no public collection internals are reconstructed.

`saga_town --data extracted/full` reads the existing resource index and APK-derived new-game defaults, loads Town.txt, runs the fresh Town data branch, ResetBuildingList and GetBuildingList, then prints permissions, ordered source triples and the indexed projection. Its scope is the Town data subsequence, not all of SelectForm.Init. It does not skip resident RNG while claiming to initialize residents. Language/DPI are explicit CLI inputs with declared defaults English.lproj/1. Shared archive/index/default readers also serve `saga_mission`; no mission is bootstrapped to obtain town state.

The base snapshot consumes TownData.firstBuild, permissions and slot19. Background mode additionally resets Area progress and binds the existing camera kernels. Building mode loads static Building data, resets KingReward received and Chara NewGame state for the reached drawing consumers. Mutable Building have/discovery remains required before town menus read it. Source triples, progress and caches remain in memory; this host does not write a save.

`--background` executes the drawing prefix through the shared CPU bitmap/SEB adapter and reports its requests. Viewer builds accept `--capture <new.bmp>` for a hidden GL capture using the existing mesh/material/submission adapters. `--width`, `--height`, `--view-x`, `--view-y`, `--camera-x` and `--camera-y` supply the declared projection context; view/form scale100 is the supported profile. Captures are partial town frames, without a claim that full SelectForm.Init or its resident RNG ran.

Generate `town-resources-v2.tsv` with `python -I tools/extract_assets.py --town-resources --out extracted/full`. It indexes the already extracted, hash-checked xls/bg/com/select/resident/select_stage archives; no Unity media is extracted again. The reader prefers v2 and accepts the earlier `town-resources.tsv` v1 for prefixes that do not need bg/com. Existing v1 and mission indices remain intact for isolated older executables. Ordinals0/2 name bg/com and13 names select_stage; no new GetResourceManager selector behavior is implied.

`--scenery` extends the background prefix through native bird/ground/cloud, floor strips and gate drawing. It initializes the cloud and decoration subsequences with separate `--app-seed 42` and `--lib-seed 42` defaults, reported with both draw counts and every row. Floor requests and font10 are reported. `--capture <new.bmp>` uses the same owner. Initialization and the first draw do not run town Update: birds start beyond the active extents and leaves are retained for their later foreground pass. The original complete Init, resident RNG and interactive form lifecycle are not implied. The public System.Random backend, SEB evaluators, viewport culling and renderer are reused; no replacement asset decoder or RNG algorithm is introduced.

`--buildings` implies scenery and draws initial construction sprites through the same CPU/GL adapter. Its report includes texture overrides, queued notices, font scopes, label/touch requests and catalog sizes. Counter0 and selected-chip-1 are native Init stores (`0x11ea108`/`0x11ea130`). Provisional inputs `--high-score 0` (int64 system save, independent of normal NewGame) and `--top-form 1` (standalone form-stack context) are explicit and overridable. Missing reached tables or providers fail. This is a fresh single-frame projection; it does not establish a persistent notice/reset lifecycle.

`--areas` implies buildings and extends that prefix through found maps and the next locked fence. Use `--camera-x 300` or449 to expose the first area without inventing discovery progress; at camera0 its x=-160 is outside the culling margin. Area selection-1, state0 and zero marks are native Init values. The provisional automatic-animation gate defaults0 and its unsupported true branch fails. Reports retain actual area names, native text-color source, font10, distinct touch profiles and queued boards/markers; glyph/color output and hit registration use the same explicit presentation stubs as building requests.

## Evidence

- Existing bounded `research/exports/select-gates/F11e9c28.asm` and `select-form-push/F11f0714.asm`: town ownership, resident allocation and draw consumers.
- Bounded `research/exports/town-entry/`: GetBuildingList, ResetBuildingList, GetLivingSubMemberArray, UpdateTownHuman and DrawTownHuman; all five have complete syntactic instruction coverage. Coverage proves available bytes, not semantic completion of the three unported resident methods.
