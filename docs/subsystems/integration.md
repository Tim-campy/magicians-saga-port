Game rules stay in their subsystem docs; this page tracks wiring. [Mission input and camera](integration-input.md) covers pointer routing, controls, replay, viewport and visibility integration. [Fresh mission endings](integration-endings.md) covers clear/game-over/retreat; [town](town.md) defines the S2 data host and remaining UI/resident boundary.

### Scene-free fresh mission (S1 A1)

`build/viewer/saga_mission.exe --data extracted/full --quest 1` opens the interactive mission from the maintainer's extracted data. The typed `MissionBootstrapOptions` owner requests the same native resource/material, NewGame record, InitWorld, formation, Stage.Start, event and per-frame providers as the diagnostic loader. It neither reads nor generates a scene file. `--scene` remains an optional diagnostic interface with its original explicit configuration; native context flags cannot be mixed into it. Fresh entry reaches [native clear, game-over and retreat](integration-endings.md) through ordinary replay actions; Continue/deserialization is a separate unbound lifecycle.

The local root requires `mission-resources-v2.tsv` (legacy `mission-resources.tsv` remains accepted), `new-game-save.tsv`, `mission-initialization.tsv` and `mission-font.tsv`; regeneration is in [setup](../SETUP.md#headless-mission-host). The font index selects LegacyRuntime by Unity identity from the verified extraction manifest, not by a hard-coded output number. Automatic selection is restricted to English/default skin; other font policies require explicit `--font`. Public FreeType supplies measurements and selected notice/Button/Debug ASCII glyphs; TextLayout block output and GUIStyle equivalence remain open.

Unresolved context has declared, overridable defaults: viewport600x640, English.lproj/DPI1, tick40ms, camera near0/far1500100/Z-1, automatic-images0/application-update1, depth24/step1, shop discovery mask1, UI-debug/short-words/held-advance/PRINT0, font/application/layout scales100, Japanese/style/load-flags/kerning0. `--help` names the corresponding options. Reports expose entry_source=data and bootstrap_context.provisional=true alongside the effective viewport/runtime. Native input starts with neutral held keys. The default Info controller is empty; no diagnostic popup rows are injected.

### Headless execution limits

The native entry requires --data/--quest and declares its host context defaults; diagnostics require an explicit scene, FPS, DEBUG, backend name and seed. Headless execution requires a frame count. Only the existing explicit-seed System.Random adaptation is available; unsupported backends and unknown flags fail. Human-enabled profiles consume FPS for attack intervals and recovery cadence, and the seeded RNG for recovery/celebration. DEBUG also reaches the numeric damage gate; effective Android values and remaining consumers are unresolved. Scene runtime rows must agree with CLI configuration. Gauge22 geometry uses the same alpha reader and scratch buffer as enemy drawing. Headless execution runs fixed logic passes without sleeping or multiplying movement by delta time. Input-enabled scenes accept ordered logical key/attack/pulse replays and [typed reached-state checkpoints](integration-replay.md); complete application bootstrap and loaded-save snapshots remain unbound.

Synthetic host tests check strict inputs and deterministic execution through the shared loader/step. Local original-data diagnostic profiles retain CPU/GPU agreement for selected effects, walking and combat states; they do not establish complete-state or Android equivalence. The current fresh-mission acceptance, full ending reports and replay checkpoints are described in [endings](integration-endings.md) and [replay](integration-replay.md).
