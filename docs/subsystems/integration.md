# Integration

How far the ported modules run together on the PC, per slice of `docs/ROADMAP.md`, and which stubs and provisional inputs the hosts use. Game rules stay in their subsystem docs; this page tracks wiring.

### Table-selected quests (S1 A1/A3)

The shared profile accepts `quest <id> <saved-rescued-count>` and loads Quest.txt from the selected `tables` archive. Missing ids/gaps fail; no synthetic record is substituted. The scenario remains an explicit mid-mission state, rather than New Game or complete Stage.Start. Human, Enemy, Stage and Map hold one StageQuest projection. The following source forms replace static numeric inputs:

```text
quest 1 0
human_system quest 0 95 0 0
geometry quest
enemy_system quest 10000
stage_notifications 1 0 0 quest 1 0 -1
stage_events quest
stage_boss quest
stage_loop quest 0 20 hold
mission_map quest
```

These illustrative state inputs are provisional: saved prisoner/completion values, Yugami, state/frame, bounds, selected attack and boss-started/fade state come from the scenario. Quest source derives distance, InitWorld map steps/quest height, chip images, enemy levels/limits/interval/pool, boss, flags and complete event groups. Enemy counters/section populations, actor equipment/progression, input, results and resource-name bindings still require their existing explicit rows. `enemy_pool` and numeric static overrides are rejected in selected-quest mode. An explicit numeric remaining-time snapshot is allowed; `stage_loop quest` instead invokes the existing native ResetTimer port with QuestData.timeLimit and the supplied FPS, preserving int32 wrap. Stage events use fresh zeroed flags sized from the actual first group; reaching an unbound event dispatcher still faults.

Local demonstration: `build/desktop/saga_mission.exe --scene research/exports/mission-data-scene/quest-table-1.txt --frames 450 --headless --fps 25 --debug 0 --rng system --seed 42 --replay research/exports/mission-data-scene/quest-table-1.replay`. Quest1 loads distance3, a 3×5 map (15 live chips) and time limit240, producing a fresh timer6000 at FPS25. The explicit near-end party state/replay reaches native boss creation, two shots, clear/result grants and held return at tick401, with 58 RNG draws; repeated reports are byte-identical. `build/viewer/queue_capture.exe research/exports/mission-data-scene/quest-table-1.txt 600 640 --run-frames 450 --replay research/exports/mission-data-scene/quest-table-1.replay` executes the same401 ticks; all91 shared report fields agree. A local tick200 capture shows the map/hero/boss combat through42 quads and14 textures, with explicit local material bindings. Party level10/EXP1499, completed byte1, rescued0, wallet/inventory, initial world/counters and replay actions are provisional scenario inputs. This is a local port run, not an original-runtime golden replay or complete-state hash.

Limits: this removes manual quest rules from selected profiles; `saga_mission --data/--quest`, automatic party/resource bootstrap, full Stage.Start, complete schedule and Android verification remain open.

### Selected movement pass (S1 A3)

MissionProfile binds the selected adapters through the actual portable SystemManager.Update dispatcher and GameplayUpdate gates. Registration follows gameplay_update_order, independently of declaration order; the manager reads each enabled flag just before its body. The host stopwatch uses C++17 steady_clock for the native Reset/Start/Stop callback shape, with elapsed durations excluded from deterministic reports. No stopwatch/runtime implementation is reverse engineered.

The nineteen available factory adapters are0/2/3/4/5/8/9/10/11/12/14/15/17/18/19/20/21/23/31. Scene choices configure their existing gates: absent input, human, spatial, movement or collision providers disable the corresponding adapters. Stage3 still uses the collection-only prefix without stage_loop, and Enemy5 requires enemy scenario inputs. Binding an adapter is not proof that its complete native body ran in every scene. Seven missing systems have no callbacks; the strict full26 make_gameplay_update_list helper remains separate and would reject those missing entries.

Replay actions precede dispatch. A Stage3 held return disables subsequent old-mission adapters except Render21 for that tick; the next step exits before replay or Input0 consumption. This is the existing documented host transition policy, not a recovered town/form cadence. Reports expose bound_update_systems, unbound_update_systems, last_update_order and update_schedule_complete. The completeness flag remains false. Battle2's native Init and inert human-AI cursor drain also execute, reported as battle_steps; no attack or Monster16 behavior is invented.


The simulate row enables optional Input -> Battle -> optional Stage Update (or collection prefix) -> Human -> Enemy -> optional Camera -> Exp -> Projectile -> Move -> Collision -> Parameter -> Emitter -> optional Cell -> Modifier -> Animation -> optional CellCulling -> Render -> Effect -> Garbage, a subset of the native ordering, without placeholder callbacks for the other systems. The complete 26-system schedule is still blocking. The optional Collision12 pass binds global pair dispatch and area delivery. The optional Stage3 collection prefix binds pickup/stage accumulation; stage_loop replaces that prefix with actual update_stage and can reach clear/result/return scheduling. Entity destruction is bound as described below; component pool reuse remains separate. mission_map fresh binds Camera8/Cell17/CellCulling20 and replaces the fixed visible group. ### Entity destruction and effect expiry (S1 A3)

MissionEntities owns the destroyed flag and stable opaque lifetime handles independently of native entity IDs (temporary entities may share native ID -1). Destroy delegates to destroy_quest_entity and delete_entity_from_manager: ascending live component removal -> disposal of component notifications -> optional registry removal -> destroyed flag store. MissionScene initializes the live And(22) subset and uses GarbagePass with factory-index31's gate. Counting finishes before deferred ordered destruction. The frame's render commands survive expiry, matching Render21 before Garbage31. The effect row calls the existing visual-effect factory with resource20, uses the selected SEB's header-derived lifetime and adds no Garbage for a looping effect.
