# Enemy creation, population and frame update

EnemySystem owns enemy creation/target selection, population quotas and the live per-enemy state pass. Its core kernels are ported; the selected desktop host binds native Init, full Update and contact/death receivers through explicit provisional quest/save inputs. The optional Collision12 pass supplies pair production and area delivery; stage startup and complete mission completion remain separate bindings; stage_notifications binds main death and boss notification.

## Overview

The host order is Human4 -> Enemy5 -> Projectile10 -> Move11 -> Emitter15 -> Modifier18 -> Animation19 -> Render21 -> Garbage31. Enemy5 executes the actual population prefix before its live entity pass, so newly spawned enemies move during the same frame. Selected enemy rows still call the raw factory (waiting state, null target); population spawns call create_system_enemy and its real SearchTarget.

## Behaviour

### Enemy creation and initial targeting

World.CreateEnemy (0x1133fc0, 1040 bytes) captures direction/data ID/level/flags/X/Y/Z. A negative ID returns null without querying the table; an ID >= the first Data.enemyData length returns null before allocation. Fetch Data.enemyData again for the indexed row: a replaced shorter array faults, and a null slot is not an invalid-ID no-op. Capture that record for subsequent reads. Component flags 1 or 2 force initial speed Z=0; otherwise call EnemySystem.GetMoveSpeed(record,level). GetMoveSpeed (0x114d870, 196 bytes) returns 0 for record flag 1; otherwise evaluate parameter 5, convert to binary32, multiply by 2.23 then divide by 100, and apply the ordered lower clamp 0.5575. These are separate operations, not a double calculation or an FPS division.

Resolve AppData.GetResourceId(record.res_) before reading clip/frame. Clip is record.seb_ unless it is -1, then wrap32(record.enemySeb_*4); frame -1 becomes 0, other values are retained. Register a type-0 non-temporary entity, then add these slots in order:

| Slot | Payload |
| --- | --- |
| 0, 5, 4 | Position from arguments with zero offsets/null parent; actual Cell conversion; Depth(0,10). |
| 7, 2 | Scalar Image(record.img_,resolved resource,-1,-1,-1,-1); Seb(resource,captured clip,captured frame,layers {-1}). img_ is read after earlier component callbacks, not captured with clip/frame. |
| 1, 24 | Speed(0,0,captured Z); Enemy(level,component flags,state 0,frame 0,data ID,target null). |
| 20 | Actual shared AIComponent projection: fresh empty CacheArray and state 0. |
| 23 | Param.Create(record,level,1000), fresh extras list and owning parameter map. |
| 6, 32 | Raw Color(255,255,255,255); actual Collision(radius 12,offset 0/5/0,visited false). |
| 12, 10 | Direction(argument,false) only when argument!=-1; playback(1,-1) only when the captured record's current flag 1 is clear. Re-read that flag after the preceding component notifications. |

No Human, equipment or Player marker is added. Earlier registration/components survive later failures. The same EnemyRecordLink, AI cache, Color, parameter storage, Cell/Image/playback and collision kernels used elsewhere are reused; no second ECS or managed collection implementation is introduced.

Param.Create(EnemyData,level,maxLevel) (0x11785f8, 304 bytes) captures PARAM_IDS and visits keys in order. GetParamValue precedes ParamHasMaxValue; unsigned key <2 uses the value as maximum, others use zero. Store id/value/maximum/caller level/caller maxLevel with all extra/EXP fields zero. Duplicate keys are still evaluated but the first record is retained, matching the already established ParamSet contract. EnemyData..cctor (0x116eee0, 208 bytes) creates independent arrays: keys 0..12; maximum interpolation levels 1000 for keys 0..3 and 200 for keys 4..12. The component factory's caller maxLevel field is 1000 for every entry; it is distinct from these interpolation limits.

EnemySystem.SearchTarget (0x114da7c, 760 bytes) retains an existing target when its entity destroyed byte is zero and a fresh target/Human lookup is alive (state neither 4 nor 5). It does not require membership or compare distances in that path. Otherwise read the current Enemy component flags. Boss flag 1 requires the stored MemberSystem and returns the current global hero directly, including null/dead/out-of-roster heroes. Other enemies capture the stored members list/version and scan it in order: require each entity/Human, skip dead humans, and read member X, enemy X, member Z, enemy Z separately. Compute binary32 dx*dx+dz*dz with separate operations; retain the first strictly smaller distance, starting at FLT_MAX. Ignore Y and HP. NaN, positive infinity and FLT_MAX do not replace the candidate. Empty/no eligible lists return null. This method returns the selection; its caller publishes it.

EnemySystem.CreateEnemy (0x114dd74, 396 bytes) calls the current BaseSystem.world_ factory and requires a nonnull result. Capture its Enemy component before SearchTarget, then store the returned target (including null) on that capture. Read live AppData.systemSave_[SYSSAVEI_YUGAMI] through SecureInt's value contract; when the value differs from 10000, re-read the current Enemy component and replace level with wrap32(level*50). The parameter map and initial movement speed were already built from the original level and are not recomputed here. Unknown save state remains a required input, with no default secure value.

EnemySystem.CreateBoss (0x114e030, 412 bytes) captures quest.bossId_ (+0x70), resolves the current world's player entity for its cache side effect (the null result is allowed), then captures a freshly resolved map.stepX. Compute GetZ(98) through the stored StageSystem, then re-read current quest.bossLevel_ (+0x44). CreateEnemy(direction 2,captured boss ID,current boss level,flags 1) at (captured stepX,0,Z). After that creation, require the stored MemberSystem, resolve the current global hero and capture its X. Compute stored-stage GetZ(96), then create an additional enemy with direction -1, data ID 1, level 1, flags 0, at (hero X,0,Z). Add type-9 modification to that additional enemy, angle 30, scale 1/1, loop true, alpha 255, other fields zero. Return the first boss entity only after all of these operations succeed; a later failure does not remove earlier entities.

Metadata scalar defaults (v31 compressed signed integers) establish EnemyComponent flags BOSS=1, FIXED=2, ACTIVE=4, independently from EnemyData flags NO_ANIMATION=1 and RUN_AWAY=2. The parameter catalog names are HP=0, MP=1, Defense=2, Attack=3, Recovery=4, Speed=5, AttackSpeed=6, HitRate=7, CritialRate=8 (original spelling), EvadeRate=9, Fire=10, Aqua=11 and Thunder=12. These names identify the indices; they do not establish unobserved UI behaviour or saved-value initialization. EnemyComponent+0x10 is level, including the post-factory Yugami transformation above.

### Stage enemy population

EnemySystem.Init (0x114c338, 588 bytes) uses its supplied World argument, not a newly resolved BaseSystem.world_. Request GetSubSet(And({24})) and store the nullable result at +0x20. In order, resolve and store GaugeSystem (+0x40), StageSystem (+0x48) and MemberSystem (+0x50). None of these results is required nonnull during Init. Allocate and publish independent zero-filled int32[10] arrays for maxCreationEnemiesNumOfSections_ (+0x58) and createdEnemiesNumOfSections_ (+0x60), then subscribe OnProjectileImpact to event 23, OnCollide to event 29 and OnHumanDead to event 30, in that order. Array initialization uses standard C++ containers; delegate combination and hash-aware removal reuse the existing EntityEvents adapter, without reconstructing runtime internals.

Init does not reset questData_, the created/defeated/remaining counters, loopCounter_, system enabled state or existing subscriptions. Reinitialization replaces both arrays and appends another set of receivers. Lookup failure preserves earlier stores and the previous value of the failing field. A subscription failure preserves all completed field/array publications and earlier subscriptions; no rollback or implicit unsubscribe runs. GaugeSystem remains a borrowed opaque service identity; no gauge rendering implementation is implied by storing it. EnemyCreationSystem shares the existing EnemyDefeatCounters storage, so creation/reset, actual damage/defeat and result accounting observe the same counters.

The registered receivers call the existing complete gameplay kernels: enemy_projectile_impact, on_contact_collision and retarget_after_human_death. Death reads the current stored subset when invoked, not the Init-time group capture. The retarget host binds search_opponent to actual EnemySystem.SearchTarget on this same state, including current member/global-hero rules. Receiver service objects and their borrowed catalogs/hosts must outlive every subscription; use one live service context for the system. Required production catalog, damage, presentation, emitter and boss-notification adapters remain explicit inputs rather than success fallbacks.

Reset (0x114c584, 108 bytes) zeros createdEnemiesNum_, defeatedEnemiesNum_ and loopCounter_ before requiring questData_. It then stores quest.enemyTotalLimit_ (+0x58) as remainingEnemiesNum_, clears the current created-by-section array to zero, then calls DestroyAllEnemies. The reached game ArrayExtension.Init<int> wrapper requires a nonnull array and leaves an empty array unchanged; the port uses std::fill for this contract. DestroyAllEnemies (0x114c5f0, 156 bytes) captures the current world before snapshotting the stored subset's live entities, requires that captured world after snapshot success and destroys each nonnull entity with registration removal. It does not re-resolve the world after callbacks or reset the ECS directory. Reset failures retain preceding counter/array writes.

CreateFixedEnemy (0x114df00, 304 bytes) captures current quest.fixedEnemyIds_[0] and a current map pointer before its loop. Each required row supplies [enemy ID, stage rate]; require the captured map and read its stepX, compute stored StageSystem.GetZ(rate), then re-read current quest.baseLevel_ (+0x40). CreateSystemEnemy(direction 2,ID,level,flags 2) at (captured X,0,Z). The map's fields and later quest level remain live; replacing the quest's rows does not redirect the captured array. Empty rows still query the map but do not require a nonnull map result. This method does not increment normal-attempt or section counters.

OnStart (0x114e4b0, 772 bytes) publishes its quest argument, calls Reset, then CreateFixedEnemy. Require the stored MemberSystem and capture the current global hero's X. Query a map and capture stepZ, read current quest height, query a second map and capture its stepZ. Compute signed int32 z=wrap32((height-2)*firstStepZ-trunc(secondStepZ/2)-50). CreateSystemEnemy(direction -1,ID 0,level 1,flags 0) at (hero X,0,Z), then add type-9 modification, angle 30, scale 1/1, loop true, other fields zero/alpha 255. Only after this initial enemy succeeds read current quest.enemyTotalLimit_ and compute quota=max(trunc(total/10),1). Capture max-by-section and fill indices <=length-4 with quota, the last three with 99999. For the ten-element Init array that means indices 0..6 use quota and 7..9 use 99999. Read live SYSSAVEI_YUGAMI; if !=10000, re-read current max-by-section and multiply every element by 100 with int32 wrapping. remainingEnemiesNum_ keeps the raw total limit. Fixed/initial creations do not increment createdEnemiesNum_. Earlier fixed/initial entities remain when a later operation fails.

CreateNormalEnemy (0x114cfd4, 988 bytes) first wrap-increments createdEnemiesNum_ even if selection later fails. Capture quest.enemies_[0], require every row's second integer and materialize weights in order before calling the exact [Random.Lot](rng.md#weighted-enemy-selection) kernel. An empty row array returns -1/no entity without a draw, retaining the attempted-creation count. A null/short row faults before any draw, including rows whose weights would have been truncated by Lot. For a selected row:

1. Capture its first integer as the enemy ID. Resolve current world/player entity (null is checked later); consume Rand(-1,1) for the column, then query the current map and capture stepX. Require the captured player and capture its Position.z. Query another current map and capture stepZ.
2. Compute stored StageSystem.GetZ(100). Convert the captured player Z using the established FCVTZS/positive-infinity override, subtract twice captured stepZ with int32 wrapping, then signed max with GetZ(100). Re-read current quest.baseLevel_. CreateSystemEnemy(direction 2,selected ID,current level,flags 0) at (wrap32(stepX+column*36),0,Z).
3. Capture the current stored StageSystem pointer before re-reading the captured player's live Z. Compute progress using that captured stage, clamp progress to [0,100], then divide by 10. Wrap-increment the current created-by-section entry. Only after that succeeds call actual EnemySystem.ChangeState(entity,1), which resets its frame. At progress 100 the section is 10; with Init's length 10 this faults after entity creation, without the walking transition. No invented final-section clamp is added.

The prefix of EnemySystem.Update (0x114c774..0x114c9ec) increments loopCounter as wrap32(old+1)%INT_MAX, captures the stored subset, then captures quest.enemyMaxNum_ (+0x54), enemyTotalLimit_ and enemyInterval_ (+0x50). Yugami !=10000 multiplies maximum/total by 100 and replaces interval with 1. Require stored MemberSystem, capture stored StageSystem before global hero lookup, then compute its progress from hero Z. The gate's section is clamp(trunc(progress/10),0,100), unlike CreateNormalEnemy's clamp-before-division. Re-read current stage and skip when boss defeated, remaining<2 or attempts>=wrap32(total-2). Otherwise require section-created < section-maximum. Count the captured group using the required-record predicate `(EnemyData.flags&1)==0`; dead states and destroyed byte are not consulted by that predicate. Spawn once only if count<maximum and the current loop counter's signed ARM remainder by interval is zero. Divisor zero retains the counter, so counter zero can still trigger it. The helper returns the captured group to the full per-enemy pass below; its spawn-gate returns do not skip that pass.

### Enemy frame update

EnemySystem.Update (0x114c694, 2368 bytes) executes the population prefix, then opens a live cursor on its captured group. Enemies spawned by that prefix are visited in the same pass. For each required entity, capture its Enemy component and HP parameter 0. These captures survive replacement of the entity's slots during callbacks; pooled records and removed payloads must remain alive until the pass returns.

1. When wrap32(HP.value+extra)>=1 and HP.rate<=99, read the captured Enemy.frame before querying HP.rate again. Set raw Color to (255,0,0,255) when ARM remainder(frame,wrap32(rate+2))==0, otherwise (255,255,255,255). Do not reset colour when HP becomes zero or rate becomes 100; stale red after healing is original behaviour.
2. Dispatch captured Enemy.state: 1 -> UpdateWalking, 3 -> UpdateBounding, 5 -> UpdateRunAway. The waiting/battling/flying-away helpers do no work; other state values also fall through. Increment the captured Enemy.frame using wrap32(frame+1)%INT_MAX after dispatch. A helper transition resets the current component's frame first; normally the outer increment then makes it 1. If slot 24 was replaced, the old capture receives the increment while ChangeState acts on the replacement.
3. Captured component flags with neither BOSS=1 nor FIXED=2 are normal. Read Map.height (+0x14) and a separately resolved Map.stepZ (+0x24), then compare current Position.z against binary32(wrap32((height-2)*stepZ)). Only ordered Z>edge, captured HP total>=1 and absence of Modify slot 15 add type 5, destroy=true, scales 1/1, maxFrame 0, alpha 255 and other fields zero. No immediate entity destruction or Garbage is added. MapSystem.LoadMap supplies height from QuestData.heightNum; its [full loader and map factories](rewards.md#mission-map-construction) are ported and composed with this enemy pass in contract tests.
4. Otherwise, BOSS/FIXED with captured ACTIVE=4 clear query the current global player entity. Capture hero Position then enemy Position; snapshot X/Y/Z after both getters. Within an inclusive X/Z radius 250, capture current Speed before resolving current Enemy.data and level, compute GetMoveSpeed, write the captured Speed.z, set ACTIVE on the current Enemy, then ChangeState(1), resetting its frame to 0 after the outer increment. HP, alive state and destroyed byte do not gate activation; a fixed state-4 enemy with HP 0 can be reactivated. ACTIVE enemies do not repeat this activation.

UpdateWalking (0x114d3b4, 588 bytes) captures current Enemy.data, re-reads current level, computes GetMoveSpeed and writes fresh Speed.z. A nonnull target with destroyed byte false is followed in X only when ordered abs(target.z-enemy.z)<150: capture Speed before fresh target/entity position queries, then write binary32((target.x-enemy.x)/30). Otherwise set fresh Speed.x=0. It does not retarget or inspect target Human/HP. Boss flag 1 additionally requires the stored MemberSystem and resolves the global hero. If enemy.z>hero.z+10, capture enemy Position, re-read the same hero's Z and clamp enemy.z to hero.z, not hero.z+10. Equality and NaN skip the clamp. Movement integration remains in MoveSystem later in the schedule.

UpdateBounding (0x114d604, 572 bytes) multiplies Speed.z by binary32 0.8. Only ordered abs(fresh Speed.z)<binary32 0.1 settles; equality, infinity and NaN return after damping. Unlock optional Direction, set fresh Speed.z=0, then boss flag 1 transitions to walking without querying stage or RNG. Other enemies require the stored StageSystem: boss-defeated means flee without RNG; otherwise require current Enemy.data and flee only if RUN_AWAY flag 2 is set and the actual Random.Hits(20) succeeds. Every other result changes to walking.

Fleeing removes existing Garbage before returning its captured payload to the pool, adds a new lifetime wrap32(3*live FPS), then stores remainingEnemies=max(wrap32(current remaining-1),1) and ChangeState(5). Pool/FPS failures preserve preceding writes; earlier zero remaining can become 1. UpdateRunAway (0x114d844, 44 bytes) writes Speed.z=-10 and leaves other fields alone. The helper does not advance frame or position; the outer pass, MoveSystem and GarbageSystem own those operations respectively. Enemy.isAlive means exactly state!=4, including fleeing; isDead is state==4. isNormal and isWaitingForPlayers are complementary checks of BOSS/FIXED and ignore ACTIVE.

The narrow activation helper CheckHitPointCircle (0x1c8b06c, 72 bytes) computes separately rounded binary32 radius*radius, dx*dx, dz*dz and their sum, returning ordered distance<=radiusSquared. It ignores Y; negative radius is squared; NaN rejects. This custom call contract needs no general engine or standard math reconstruction; the port uses C++ arithmetic and std::fabs, reusing existing RNG, parameter, state, modification and Garbage modules.

## Port

MissionHumans calls initialize_enemies after Human Init and before Projectile Init, replacing the manually registered Enemy impact receiver. EnemyEventServices borrows the same owner, catalogs and RNG for its lifetime. Event23 runs Human -> Enemy -> Projectile; event29 runs Human -> Enemy; event30 retargeting calls search_enemy_target. Gameplay human-death delivery runs Stage before Enemy retarget. Main game-over requires stage_notifications; sub-character death skips game-over and still reaches retarget. See [notification binding](integration.md#stage-death-and-boss-notifications-s1-a3a4). Gauge lookup is an explicit HUD service stub, and contact sound is an audio stub; neither suppresses contact state/effect mutations.

Explicit enemy_system/enemy_population/enemy_pool profile rows enable update_enemies with its real population prefix and factory-index5 gate. They supply Yugami, quest population limits/interval/base level, initial counters/boss flag and uniform section limits/counts. The same StageQuest object is used by Human/Stage/Enemy adapters. The existing 256-cell lottery scratch and counted RNG are shared across population calls. No Stage.OnStart is invoked merely to initialize the scenario: it would destroy the selected group. See [integration](integration.md#table-backed-enemy-init-frame-and-population-s1-a3) and [setup](../SETUP.md#headless-mission-host).

The host tests cover fixed activation/movement, same-frame population/target assignment, the alternate Yugami cadence/level branch, repeatability, strict input groups and conflicting reward counters. The C++ MissionHumans contract sends actual ordered contact events, advances recoil to walking and verifies retargeting excludes a dead party member. A synthetic selected-frame shot profile can invoke Defeat twice while two shots are in flight before corpse expiry: the existing no-local-guard rule preserves two pending EXP/treasure pairs. This partial-schedule observation does not establish Android duplicate-reward behavior; caller/collision guards remain unresolved.
