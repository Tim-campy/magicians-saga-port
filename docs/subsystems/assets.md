# Assets and resource pipeline

All shipped resources of the 1.4.0 APK (SHA-256 `d58943e6…6eead`) are catalogued and extracted: 38 TextAssets (30 XOR-obfuscated JarInflater containers holding 1,963 members) plus Unity textures, FSB5 audio and TrueType fonts. The on-disk JarInflater, SEB (modes 0/1) and regular OPT formats are proven by assembly and byte-exact round trips, and each has a C++17 reader in `src/assets/` with contract tests. Visible-entity draw-command production and the game's depth-sort queues are ported and composed with the combat/camera/visibility test. The runtime resolution chain (INF catalog -> ResourceManager ID -> Image/OPT -> Seb sprite) is not closed end to end; scene pixels, audio playback and comparison with Android remain open.

## Overview

Layers, outermost first:

1. **APK / Unity serialized files.** 1,184 `assets/` members form 1,182 logical files (1,149 Unity serialized v22, 33 other). The only split group, `globalgamemanagers.assets.split0..2`, is concatenated in numeric order in memory (2,953,096 bytes). One build scene `Assets/Scenes/main.unity` (`level0`) holds GameObject `Main` with `main.Main`, `system.tapjoy.MyTapjoy`, `system.notification.FCMReceiver`. Unity 2022.3.62f2. See [unity-media](../formats/unity-media.md).
2. **TextAssets.** 38 objects; 30 start with `65 b6` and are XOR-obfuscated containers, 8 are kept verbatim (6 readable UTF-8: `language_pack_template_ja/en`, `language_pack_format`, `BillingMode`, `snd`, `filelist`). Read in game by `kairo.unity.io.AssetReader`; `GetData` reaches `Encrypter.Decode`. See [jar-container](../formats/jar-container.md).
3. **JarInflater containers.** Decoded payloads are a name-indexed archive parsed by `JarInflater._load`; lookups go through `JarInflater.ConvertExtension`/`_search` (name aliases, language candidates).
4. **Catalogs.** Per-container `img.inf` / `seb.inf` map explicit decimal IDs to member names with options (`bin`, `u`, `q+1`, `WxH`, ...). `ResourceManager.LoadReady`/`LoadStart` parse them and store images by ID in `ResourceManager+0x10`. See [inf](../formats/inf.md).
5. **Images.** `kairo.unity.ui.Image` wraps a Unity Texture2D (`DecodeByteArray` -> `UnityUtil.LoadImage`). An optional `<name>.opt` grid (path from `Image.GetOptionFile`) remaps a packed PNG into logical cells. See [opt](../formats/opt.md).
6. **SEB sprites/animations.** `Seb._load` parses groups of records into compact runtime buffers; `GetSpriteLocal` selects a record by FrameNo; `ConvBufferToSprite` fills a 12-slot `Sprite` int array (FrameNo, TexId, U, V, W, H, X, Y, ReverseU, ReverseV, Blend, Color); `Seb.GetImage` resolves TexId through `ResourceManager.GetImage`. Frame advance is in `Seb.Frame` / `ThisFrameRenderAnimation`. See [seb](../formats/seb.md).

Extracted corpus (local, never distributed, `data/extracted/manifest.json` schema 2 / `data/full` schema 3): 973 PNG, 303 SEB, 286 OPT, 286 OPTINFO, 63 INF, 47 TXT, 3 CSV, 1 BIN, 1 MAB. All 973 PNGs pass Pillow `verify()` + `load()`; none exceeds 1,024 px on either axis (RGBA8 expansion of all would be 53,709,576 bytes; not a VRAM/3DS measurement).

## Behaviour

**Key derivation (method, no key bytes).** `main.AppData.Init` (0x1100298) allocates an 11-element int array (0x110062c), fills it with `RuntimeHelpers.InitializeArray` (0x1100640), expands the eleven ints into 44 little-endian bytes (loop to 0x11006c0) and calls `SetEncryptionKey` at 0x11006e4. Other `SetEncryptionKey` call sites exist in `ApplicationManager`; the key is not proven global/immutable. The initializer is metadata field 24349 (`<PrivateImplementationDetails>`, offset 4557992, length 44, default-data index 188696), resolved via code ref 0x272fa50 -> reloc 0x27ea1c0 (value 0x800000f5, usage 4 / fieldRef 122, type index 8809); its SHA-256 matches its generated name. The extractor reads it from the hash-verified user metadata and embeds no key.

**Name aliasing.** `Config.ConvertExtension` reads the first int of Config static storage (`class+0xb8`, offset 0). `Config..cctor` initialises that block from ELF 0x625fb0 to `(2,0,100,30)`, so the selector starts at 2 (later writes not excluded). `StringUtil.Replace` (0x1c19534) replaces **every occurrence** (IndexOf from 0, mode 4, loop) — not a suffix swap; do not use `Path.ChangeExtension` semantics there. `JarInflater.ConvertExtension` then uses `Path.GetExtension` + `ToLower` + `Path.ChangeExtension` for `.inf`/`.ini` -> `.txt` (true final-extension rule), only when `this+0x20` (path prefix) is non-null. Literal indices: `.gif` 1037, `.png` 1050, `.mld` 1044, `.ogg` 1046, `.inf` 1039, `.ini` 1040, `.txt` 1055, `.bytes` 1020, `.opt` 1047, `bin` 10179, `gif/png/jpg` 11283/12529/11765.

**Lookup order.** `Exist`: ConvertExtension, then prefixed `CheckResourceAsStream` if `+0x20` set, else `_search != null`. `_search`: null if name or dictionary null; first candidate (lower-cased) present in the dictionary wins. `GetInputStream`: prefixed stream, else `_search`; a found record may be served by `AssetReader.GetCustomResource` (field `+0x28`). `GetData`: `Storage.Read(prefix+name)`, then `GetSize`/`GetInputStream`; size -1 returns null. No direct cross-container fallback (e.g. `07_room` -> `09_shop`) exists in these bodies.

### Resource file candidate order

The portable `resource_lookup` cluster binds Config.ConvertExtension -> AssetReader.GetAccessFilesList -> JarInflater._search. It reuses the existing UTF-16 `split_trimmed_text_fields` implementation, and standard strings/containers implement the already-established contracts; no Mono/.NET, locale engine or dictionary implementation is reverse engineered here. Confidence high for static ordering; actual application locale/density and async loading still need production bindings.

AssetReader stores country/language at static +0/+0x8, DPI index +0x10 and DPI_FOLDERS +0x28. The static initializer installs [drawable-ldpi, drawable-mdpi, drawable-hdpi, drawable-xhdpi]. GetAccessFilesList first calls _init only when country is null; an empty nonnull country suppresses initialization. _init reads DisplayMetrics' binary32 density, calculates density*160+0.5, converts to int32 with the native conversion and chooses unsigned 0..139 -> index0, 140..179 -> 1, 190..249 -> 2, signed >=250 -> 3. Values 180..189 and other unmatched conversions retain the prior index. It then obtains JLocale.GetDefault, lowercases its language and stores it at +0x8 before lowercasing/storing country at +0. The desktop candidate function leaves this platform/locale initializer behind an explicit callback, rather than inventing Android density from PC DPI.

After initialization, call Config.ConvertExtension with the current selector, then Split on literal slash using trim=1/excludeEmpty=0/escape=0. This existing game helper trims U+0000..U+0020 from **each segment**, retains empty segments for nonempty input and returns zero parts for null/empty input. GetAccessFilesList requires the last part as filename, so zero parts fault; preceding parts are concatenated with a trailing slash as directory. Backslashes, duplicate slashes, dot components, case and non-ASCII whitespace are not normalized here.

Build a suffix list in this order:

1. Only when Language static +0xb8 is nonnull **and** get_UseResourceLanguage returns true: capture the freshly reread array and append each entry plus slash, in array order. A null element concatenates as empty and yields slash. A null array suppresses the getter itself; nonnull empty still calls it.
2. Always append Language.GetFolder() plus slash, even when UseResourceLanguage is false.
3. Append the empty suffix.

Language.GetFolder() at 0x1b1ff7c captures FOLDERS at Language static +0x18 **before** calling Language.Get() at 0x1b1b208, then bounds-checks/returns the captured array's selected element. Get does not read UseResourceLanguage in this body; the flag's getter/setter operate on a separate runtime-selected byte as inverse / inverted low bit. Thus false disables the pack-folder prefix stage here, not the independent primary-language-folder call. Folder selection and current-culture casing remain typed providers. A null/empty folder value concatenates to slash, not the empty suffix.

Starting with the captured signed DPI index, enumerate DPI_FOLDERS[index..end) in ascending order. For each DPI folder, enumerate every suffix and append directory + DPI folder + slash + suffix + filename. Then enumerate DPI_FOLDERS[index-1..0] descending, with suffixes in the same order. Finally append directory + suffix + filename for every suffix, without DPI. There is no deduplication, global container search or existence filtering. An index equal to array length starts the descending phase; other out-of-range accesses fault rather than clamp. Example: index1 in [lo,mid,hi], pack [custom], primary English.lproj yields all mid/custom, mid/English.lproj, mid/root candidates, then hi, then lo, then candidates without DPI. An empty primary folder yields /filename before filename.

JarInflater._search (0x1bfc468) returns null immediately for null input or absent dictionary. Otherwise call String.Trim, JarInflater.ConvertExtension, String.ToLower, then GetAccessFilesList. Its Config conversion is therefore performed **again after lower casing**: uppercase .GIF survives the first ordinal conversion, becomes .gif when lowered and can become .png inside candidate generation. For each candidate, require it, capture the current dictionary, lower the candidate and query that captured dictionary; the first success returns the original member. No match returns null. No exception is caught here. The portable result is an opaque host member index; source archive bytes/lifetimes stay with the host. The prefixed JarInflater path/extension conversion is still a provider, not approximated by a filesystem suffix operation.

Tests compose this lookup with catalog supplementation and existing ID indexing: a custom-pack img.inf wins, disabling pack lookup selects the primary-language img.inf, missing IDs are filled from it and selected entries retain priority. These are synthetic data and explicit language inputs; they do not establish which locale an Android run selects.

### Selected archive to pixels

`ResourceArchive` now owns one decoded Jar archive and exposes indexed img.inf/seb.inf catalogs plus a selected sprite binding. It supplies the explicit ASCII/invariant text profile through public C++ classic-locale operations, reuses the existing ASCII decimal parser and rejects non-ASCII input. All 1,963 shipped member names and 51 catalog texts were checked as ASCII (after UTF-8 BOM removal). The caller supplies language folder and DPI; Config selector is the observed initial 2, with no pack overrides. This profile closes selected-file preparation, not the application's unknown locale/bootstrap state or asynchronous loader.

Catalog framing removes an initial UTF-8 BOM, splits LF, drops only zero-length segments and retains CR for this Unity 2022 profile, then calls native selected-row normalization, LoadStart row-prefix parsing and ID indexing. Empty slots and duplicate last-row placement remain visible. A selected animation ID resolves its specification through GetFileName and the native archive lookup; its parsed SEB is evaluated at the requested frame/layer, and the resulting TexId selects the indexed image specification. SEB u/v/c apply the existing reverse/cache kernels, and supported image options are bin, WxH and relative queue q+N/q-N; Image.GetOptionFile resolves the optional regular OPT independently through the same lookup. Other selected image options fail explicitly. PNG decoding/limits and the technical SDL color/matrix profile are reused, with no new decoder, rasterizer or implicit cross-container fallback.

The optional viewer accepts decoded.bin --resource clip frame layer --language folder --dpi index --canvas width height. It no longer requires PNG/OPT filenames or a manually supplied image slot for this mode. JSON identifies the selected catalogs/members, clip/TexId and explicit resource text profile. This archive preparer is a reusable desktop library for the next mission binding; the 120-pass combat scenario still uses recorded graphics and synthetic resource slots.

Local captures prove actual enemy clip6 -> m.seb -> TexId100 and character clip41 -> ch_walk_right.seb -> TexId0 reach SDL pixels through catalogs. Their captures were inspected visually and are byte-identical to the earlier captures with manually bound PNG/OPT files; this compares two paths inside the port, not Android. Effect clip101 -> impact_effect_00.seb -> TexId64 uses q+1; enemy clips4/5 and character clip42 use u. Their loading contracts are now ported below. Indexed SEB manager preparation and duplicate-file instance separation are implemented below; atlas/image-cache identities, full image readiness and scene depth/material batching remain separate work.

### Ready catalog manager and duplicate SEBs

`ResourceArchive.animation(id)` and `image(id)` now cache successful selections by catalog ID and return stable references. Parsed SEBs, image bytes and OPT metadata no longer need to be copied or parsed on each resource lookup. `sprite` remains a diagnostic copy-producing convenience. Failed selections are not published. This is synchronous desktop preparation, not a reconstruction of the native task queue or its partially loaded state.

In the LoadStart closure, the normalized first filename token is stored before searching earlier slots (0x1baabd4..0x1baac24). The comparison calls public `System.String.Equals(String)` at 0x1ced054. Its [documented ordinal, case-sensitive contract](https://learn.microsoft.com/dotnet/api/system.string.equals) is implemented with ordinary std::string equality in the supported ASCII profile; no runtime string algorithm is reconstructed. Equality is on the filename token **before** archive lookup, not on the resolved lowercased member: `clip.seb` and `CLIP.SEB` can resolve to the same member but do not take the duplicate branch. On the first equal earlier filename, a nonnull earlier SEB is passed to a **fresh** Seb(Seb); a null earlier object falls back to ordinary loading. Both branches join before SetReverse and optional SetCacheSize, so later options do not modify the earlier instance.

`Seb(Seb)` (kairo:0x0600175f, 0x1bab9fc, 352 bytes) creates fresh offset storage (two int32 cells) and instance work, then requires the source. It copies name (+0x10), maxFrame (+0x1c), the four record-array references (+0x20/+0x28/+0x30/+0x38), boundingRect/boundingRects/boundingRectsEx/pixelBoundingRects (+0x50/+0x58/+0x60/+0x68), the 20-byte pixelBoundingRect value (+0x70..+0x83), and Resource (+0x88). Current frame (+0x18), reversal (+0x40), cache (+0x48) and final Flip (+0xb0) retain fresh-object zero/null values; instance work (+0xa8) is not shared. Thus raw sprite records are shared while clocks, reversal, cache and evaluation work remain distinct. This is a constructor, not assignment to an existing object.

[ArchiveResourceManager](../../src/platform/desktop/archive_resource_manager.hpp) synchronously builds the complete indexed SEB array, preserving gaps and catalog IDs. Its sprite projection uses `clone_seb_sprites` for equal earlier filenames, shares exactly the represented record arrays and applies each row's u/v/c independently. The desktop viewer now feeds this ready manager directly to AppData.DrawZSortObjects at the original selected clip ID, rather than rebuilding that clip at slot zero. The constructor's bounding/resource/offset fields are not yet represented in the port, so its registry stage remains documented rather than reimplemented.

Image slots start null and require explicit `bind_image(id, readyImage)` from the host. The object is borrowed; its native dimensions, OPT preparation, texture ownership and cache/atlas identity remain the host's responsibility. Catalog standard-resolution and queue options must match; failed bindings retain the previous slot. Null unbinds a present catalog slot. Unrelated unsupported image options do not block SEB preparation, but selecting/binding such an image still fails. This avoids inventing native image-sharing or async-readiness policy. The selected viewer uses the existing public stb_image decoder and existing OPT preparation. [Contract tests](../../tests/test_archive_resource_manager.cpp) exercise shared record identity, separate clocks/caches/options, case-sensitive duplicates, retained bindings, original IDs, direct AppData consumption and the QuestForm logical-viewport/world/cleanup callback with recorded graphics.

Local `research/exports/manager-preview/ready-captures.json` records complete SEB preparation for the selected enemy catalog (48 ready / 48 slots), character catalog (57 / 201) and effect catalog (6 / 105), retaining the gaps. Enemy clip4, character clip42 and effect clip101 captures are byte-identical to the prior selected-file captures in resource-options-preview. This checks the new manager path inside the port, not Android behavior. The pixel harness also covers a later u/c3 SEB cloned from an earlier v/c2 entry at a different catalog ID.

### Complete synchronous image preparation

[ArchiveImageSet](../../src/platform/desktop/archive_image_set.hpp) prepares every present image catalog slot through a supplied decoder, builds distinct Image/regular OPT objects at their original IDs, sets standard dimensions and relative render queues, and computes native Image.GetAlphaType through the existing classifier. Gaps remain null. The bin load branch allocates a fresh Image for each processed row (0x1bab374..0x1bab390); SEB duplicate sharing must not be applied to these Image objects. PNG decoding reuses the existing pinned public stb_image implementation in [decoded_image.cpp](../../src/platform/desktop/decoded_image.cpp), separated from the viewer for reuse by a mission host. No decoder or Unity texture implementation is reconstructed.

The desktop profile remains RGBA8 PNG, at most 8192 pixels per axis and 16 Mi pixels per image, with at most 64 MiB encoded input and an explicit total decoded-RGBA budget (default 128 MiB). These are host memory limits, not original game constants or 3DS measurements. All selected images are prepared before publishing bindings, so a missing/corrupt image, unsupported reached service, bad decoder result or budget failure leaves earlier host bindings intact. This atomic desktop preparation does not claim native asynchronous failure/partial-publication ordering. ### Loading flags and relative material queues

The [INF contract](../formats/inf.md) now records SEB first-character u/v/c parsing and image q+N/q-N parsing. ### Visible-entity commands

`RenderSystem.Init` (0x1160ca8, 108 bytes) requires the supplied world, stores its nullable map at +0x28, then stores a fresh int32[32] scratch at +0x30. It does not clear the draw queue or register a subset. `Update` (0x1160d30, 4,124 bytes) obtains current QuestForm camera offsets, calls the current width and a freshly obtained form's height, and discards both dimensions. These calls are outside its entity-loop catch. Scheduler gating is already established in [ecs](ecs.md); the renderer itself does not clear the queues.

The loop uses World's visible HashSet (+0x40), preserving slot order and version invalidation through the existing public-HashSet adapter. It skips Invisible slot 21 or absent Position slot 0. Screen coordinates are native int32 conversions of binary32 `x-z` and `(x+z)*0.5-y`. Each conversion preserves the original positive-infinity result of INT32_MIN. For Cell slot 5 it requires Cell twice, then updates Depth slot 4 with binary32 `y+x+z+extra+overlay`: `extra` is signed `wrap32(rate*depth.extra)/100`, rate initially 100; overlay is 9,999,999.0F for Fukidashi slot 18 or Gauge slot 19, otherwise zero. Without Cell, existing Depth.value is retained. The map stored by Init is unused by this body.

Resource selection captures current AppData and fresh Seb slot 2 resource ID, obtains the selected ResourceManager's clip array, and indexes a freshly read Seb clip ID. SyncAnimation slot 13 selects the shared clip clock; otherwise it captures the entity's Seb frame. A single layer value -1 requests all layers through `Seb.GetLayersNum`, filling the persistent 32-cell scratch without growth; count 33 fails after storing indices 0..31. Other layer arrays keep their original reference and captured length; later callbacks may replace the component's array without replacing the captured array. Elements remain live, and -1 entries are skipped. Image slot 7 is captured once before layer processing.

Each layer calls `Seb.GetSprite(frame,layer)` and reads U/V/W/H at result indices 2..5. This result is a runtime sprite, not a direct crop of the PNG or a disk SEB record. Image overrides apply in this order: texture ID, image-resource ID, resource -2 early skip, U/V/W/H arrays, texture -2 late skip. Singleton arrays apply to every layer; crop -1 preserves the sprite value; shorter arrays fall back. Required null arrays and negative indexed layers fault.

Base alpha comes from Color slot 6 or 255. ModifyAnimation slot 15 scales width/height with binary32 multiplication and native conversion, adds modifier x to screen x, and adds modifier y plus the original-minus-scaled height to screen y. Anchor bit 2 additionally adds half the width difference; bit 32 subtracts half the height difference; signed division truncates toward zero. **These x/y changes accumulate across layers**, rather than resetting for each sprite. Modifier alpha <=254 becomes `wrap32(alpha+1000)`; larger values retain base alpha. Type 9 sends angle as skew; other types send zero. Modifier z is unused here.

Immediately before insertion the body captures current AppData again, then reads fresh Seb resource, Depth.value, Seb clip and Color RGB. Missing Color produces color -1. Camera offsets and frame retain their earlier captured values. All arithmetic on int32 positions/depth wraps.

`InsertZSortObject` (0x111586c, 800 bytes) takes 20 arguments: the following 19 cells plus `type`, which selects an outer queue. RenderSystem always selects type 0.

| Cell | Meaning |
|---|---|
| 0 / 1 | Texture override / Seb resource ID |
| 2 / 3 / 4 | Depth plus layer / Seb clip ID / captured frame |
| 5 / 6 | Screen x minus camera x / screen y minus camera y |
| 7 / 8 | Scaled width / scaled height |
| 9 / 10 | U / V |
| 11 / 12 | Source width / source height after Image overrides |
| 13 / 14 / 15 | Layer / alpha / packed RGB or -1 |
| 16 / 17 / 18 | Angle / image-resource override / skew |

AppData +0x3d0 holds counts and +0x3d8 holds row buffers. Insertion grows the selected buffer by 128 rows, preserving old row references and allocating new int32[19] rows; it publishes growth before accessing the count-selected row. Each field writes sequentially, and the count increments only after all writes. A malformed short row retains its written prefix. Clear resets counts only; subsequent commands reuse rows. This is application behavior, not a reason to reconstruct a managed allocator.

`Zsort()` (0x1115b8c) sorts category 0 before 1. The typed overload (0x1115bac) computes `wrap32(count-1)`, skips a negative end, and otherwise calls QuickSort (0x1115c10). Pivot (0x1115cc4) scans from left+1 for the first depth unequal to the left depth, choosing the larger depth's index; equal ranges return -1 unchanged. Partition (0x1115d50) scans left while depth is less than pivot and right while depth is greater than or equal, swapping row references. QuickSort recurses left and iterates right. Ties therefore are **not stable**: depths `[2(A),1(B),1(C)]` become `[1(C),1(B),2(A)]`. These small private game helpers are retained because `std::sort` and `std::stable_sort` promise neither this exact order nor its row reuse; storage and swaps use the standard C++ library.

The native LSDA resolves the loop catch to `System.Exception`: visible-cursor acquisition, enumeration, component reads, sprite queries and insertion are inside; viewport queries and final `Zsort()` are outside. A caught failure stops the entire loop, logs the current entity when nonnull, retains already queued commands, then sorts that prefix. Logging failure propagates before sorting. A version change at the next cursor step still names the last entity. A failure before selecting an entity is not logged. No queue rollback or implicit clear occurs.

### Command consumption

`AppData.DrawZSortObjects(Graphics,type)` (0x1115e54, 2,548 bytes) increments `this+0x3e0` with wrapping int32 addition and signed remainder20 **before validating Graphics**. It obtains Graphics.GetMeshManager once, then reads the selected current count before every row. It neither clears nor sorts queues. A null mesh is permitted when no row is processed; otherwise each row first sets `MeshManager+0x44 = max(depth,0)/150000`, then calls SetDepth with remainder150000 and layer 0, even if the row's resource/sprite is subsequently skipped.

Resource resolution uses **this** AppData.GetResourceManager with the row's resource ID. A null manager skips the row. It indexes that manager's shared SEB array by row clip, evaluates GetSprite(row frame, row layer), then skips a null sprite or TexId exactly -1. Graphics+0x40 is set to 1/2/3 only for sprite ReverseU/ReverseV exactly 1 (horizontal/vertical/both); absent flags retain prior graphics reversal. The shared sprite reference remains live during later callbacks.

Normally Image is `selectedManager.images[sprite.TexId]` (+0x10), with required references and strict index checks. A row texture override other than -1 is considered only for resource IDs **1,2,3,7,18,19,20,21,22,23** (mask 0x00fc008e). For those resources, row image-resource !=-1 obtains a manager through the **fresh global AppData**, then a nonnegative in-range texture chooses that manager's image. An invalid texture emits a diagnostic with original resource/texture/clip/layer and leaves Image null; it does not fall back to the sprite's texture. A selected null Image emits another diagnostic with original resource/sprite TexId and still reaches the draw call with null. Negative override IDs bypass image-array validation before diagnostics, but nonnegative IDs require the selected manager/array. Other negative sprite TexIds are not universally skipped: without a valid applicable override they fail the normal image index operation. Command interpretation in the separate Seb drawing paths must not be invented here.

Width/height, U/V and source width/height each fall back to the corresponding sprite W/H/U/V when their row cell is -1. The resulting six integers are captured before graphics-state callbacks. Row alpha 255 performs no render-mode push. Other values pass signed quotient/remainder1000 as follows; all arithmetic/range comparisons retain int32 behavior:

| Encoded alpha | PushRenderMode arguments |
|---|---|
| -999..999, except 255 | `(alpha/1000, alpha%1000, 0)` |
| 1000..2999 | `(alpha/1000, alpha%1000, 255-alpha%1000)` |
| 3000..3999 | `(1,255,alpha%1000)` |
| Other values | No push; the later alpha !=255 cleanup still pops |

After that push, the body validates sprite Color cell 11's existence without using its value. Row color !=-1 calls PushBlendMode(2,color). A nonzero angle reads row skew: nonzero skew calls FastMath.Tan with binary32 angle, supplies a 3x3 identity with element1 replaced by the result to current Matrix.SetValues, then freshly obtains the matrix for PreTranslate(0, `tan * binary32(wrap32(-sourceWidth)) * 0.5F`). Zero skew instead calls current Matrix.SetRotate(angle, -sprite.X, -sprite.Y), using wrapped negation and binary32 conversion. It then pushes the freshly obtained matrix. The selected desktop adapter now binds these calls to the narrow native matrix/stack contract below; the consumer still accepts explicit graphics services. Public double-precision libm implements trigonometry.

Destination position is binary32 conversion of wrapped `row.x+sprite.X` / `row.y+sprite.Y`, read after transform callbacks. If destination and source dimensions both match, call Graphics.DrawImage; otherwise call DrawScaledImage with integer source crop and binary32 destination dimensions. The image may still be null. Successful drawing then **rereads** row angle/color/alpha: nonzero angle resets the current application matrix then pops Graphics matrix; color !=-1 pops blend; alpha !=255 pops render mode. Finally it rereads sprite reversals and clears Graphics+0x40 only if either equals 1. Thus callbacks that change row/sprite fields can change cleanup, and exceptions leave the current state/prefix untouched. No catch/finally cleanup exists in the bounded assembly; its FDE has no LSDA.

### Bitmap source, UV cache and vertex contract

The reached `Graphics._drawBitmap` (0x1b66080, 7,480 bytes) takes an Image and eight binary32 values: destination x/y/width/height and source u/v/width/height. It is called by the ported rectangle/regular-OPT path. Source/atlas, sampling-cache, rectangle geometry, local matrix scopes and ordinary texture color passes are ported here. Grayscale creation, material/render-queue orchestration, text/balloon/touch tasks and final accounting still prevent claiming the complete caller. Confidence high for the bounded slices; live graphics state remains unverified.

For `Image.passes == 0` or a nonnull decoded frame table, each positive standard dimension scales the corresponding source origin and extent by `binary32(Image dimension) / binary32(standard dimension)`. Regular OPTs skip this second scaling. The four grayscale-key integers use native conversion of `value + 0.1F`, before atlas offsets (including the existing positive-infinity-to-INT_MIN rule). An active atlas region requires its owner and page Image, captures signed int32 u/v offsets, queries the original image alpha type, offsets only source u/v, then stores that alpha type on the page. An inactive or absent region retains the original image. Atlas page population and grayscale image lifetime are still host inputs; no atlas is synthesized.

Graphics.renderCache_ (+0x2d0) retains image identity (+0x10), alpha type (+0x18), four source-key floats (+0x20), normalized UV bounds (+0x28), valid-crop (+0x30), material/builder arrays (+0x38/+0x40), material count (+0x48) and dirty (+0x4c). Dirty or a new image forces a crop recomputation. An unchanged image queries alpha once for equality and again for storage; an alpha difference also sets dirty. Otherwise exact float equality of u/v/source-width/source-height reuses UVs (NaNs miss). The source key is stored before clipping; a short key retains its written prefix on failure. Dirty is cleared only later, after material emission, which restores the original image identity rather than the atlas page.

Clipping uses `FMAX(source origin,+0)` with NaN propagation. A negative origin changes its extent candidate to `origin + extent`; otherwise retain the extent. Clamp the far end to the page Image width/height. Validity tests the resulting extents strictly greater than zero. **This does not move or shrink the destination.** On a cache miss only, the call-local source extents become those clipped values; a hit preserves the incoming extents, which matters to later accounting. A NaN origin with positive finite extents can still have valid-crop=true and NaN UVs.

For a valid crop, the source work bounds are `(left+0.005F, top+0.005F, (left+width)-0.01F, (top+height)-0.01F)`, preserving binary32 operation order. Positive extents smaller than the inset can yield reversed UV bounds; they are not repaired. Texture virtual dimensions, not Image dimensions, normalize this rectangle. Queries occur width, height, width, height, height. With the first pair used for normalized extents, the second width for u and the last two heights for v: `u=left/width2`, `v=((height2-cropHeight)-top)/height3`; right/bottom are u/v plus normalized extents. Bottom-left UV convention maps rectangle corners to `(u0,v1),(u1,v1),(u1,v0),(u0,v0)`.

`GetTransRectGL(RectangleF,vertices,fillBounds)` (0x1b68058, registry kairo:0x0600139a) reads left/top and width/height and forwards to its scalar overload (0x1b69ee8, kairo:0x0600139d) with transform=true. The scalar overload takes x/y/width/height, optional Vector3 output, transform flag and optional fill bounds; null output allocates four points. It writes TL, TR, BR, BL sequentially, preserving an existing array's identity and length. A short array fails after the available XY prefix; Z writes start only after validating the selected mesh coordinate mode. It uses Graphics.meshId_ (+0x7c) to select meshManList_ (+0x80). When the selected manager's +0x18 flag is set, Y's origin is the bound Surface height, else live render-target height, else screen height; without the flag it is zero. For every output point, including retained points beyond index 3: set Z=0, optionally apply screenMatrix_.MapPoints, then Y=origin-Y. Original XY (or indexed corners of fillBounds) feed optional beginFill_ && callDrawBitmap_ lookup; an existing fill point replaces transformed XY, otherwise the transformed point is inserted. Surface/target dimensions, screen matrix and fill lookup are explicit typed services, not Unity internals reconstructed instruction by instruction.

Destination bounds expand each side by half the effective shared Graphics expansion value. Material emission uses triangles `(0,1,2),(0,2,3)` in the inspected MeshBuilder path. SDL's existing `SDL_RenderGeometry` handles rasterization; the adapter converts the established bottom-left vertex/UV convention to SDL top-left coordinates. Its current selected-sprite profile is an explicit identity world matrix with native local transforms, no atlas, zero expansion, ordinary native texture blend/color passes and no UI tasks (--raw-rgba retains diagnostic replacement). Public SDL 3.4.18 software QueueGeometry truncates UVs to integer texels before interpolation (`src/render/software/SDL_render_sw.c:618`), which loses the native inset and repeats texels. The selected-sprite profile therefore rejects that backend; headless capture uses an invisible graphics-backed window and SDL_RenderReadPixels. PNG and occupied-bounds OPT capture retain their existing software renderer. A desktop graphics/video driver is required for selected-sprite capture, even without a visible window. Unsupported local-coordinate/material or external-image services fail; this profile is not inferred production state.

### Reached sprite matrix and stack contract

This cluster unblocks SEB reversal flags and command rotation/skew on the same selected mission sprite path, including OPT piece offsets under a flipped parent transform. The [public AOSP Matrix API](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android11-gsi/graphics/java/android/graphics/Matrix.java) was consulted first (blob cf914c2c3eae590c191048ed0542c798ba1dfcbc, Apache-2.0). Its row-major public layout differs from this KairoLibrary adapter. No AOSP or Unity reference implementation is copied; the [Unity 2022.3 reference](https://github.com/Unity-Technologies/UnityCsReference/blob/2022.3/Runtime/Export/Math/Matrix4x4.cs) has a reference-only license. Reconstructing Unity/Skia internals is unnecessary: SDL rasterizes the resulting vertices and C++ libm supplies trigonometry. Confidence high for the static adapter contracts, pending Android comparison.

`Matrix` owns a column-major binary32 array at +0x10 and retained concat/rotation scratch at +0x18/+0x20. Reset copies nine ordinary identity values into the existing array; a longer destination retains its tail. SetValues copies the **source length**, while Set(Matrix) copies the **destination length**; range/null failure occurs before copying. Return value is the same Matrix object for the mutating operations. PostConcat(array) computes other * this; PreConcat(array) computes this * other. The 3x3 loop visits columns, rows and k=0..2; each binary32 multiply and add is separate, starting at +0, and writes the partial sum after every k. Scratch is allocated once if null and fully zeroed first. Input/output/scratch aliasing and a failed partial sum remain observable. SetConcat(Matrix left,right) checks both objects, copies left's source-length array, then PostConcat(right's array); a null right array can therefore fail after the left copy.

MapPoints(ref x,ref y) (0x1ba4a3c) requires array index 6 before capturing XY, computes `x=m6+(oldX*m0+oldY*m3)` and `y=m7+(oldX*m1+oldY*m4)` in that binary32 order. It does **not** divide by a perspective coordinate. A seven-element array writes X then fails before writing Y. The earlier vertex doc called this TransPoints; metadata confirms its name is MapPoints.

PreTranslate updates the last column using each row's two products, their sum, then addition to the existing translation/homogeneous value. PostTranslate adds x/y times each column's third element to its first/second elements; each third-element bounds check precedes that pair's writes. PreScale scales the first two columns, bracketed by PreTranslate(+pivot), PreTranslate(-pivot) for a nonzero pivot; PostScale scales the first two rows, bracketed by PostTranslate(-pivot), PostTranslate(+pivot). SetScale and SetTranslate reset first. Scale and translation reject NaN arguments but **allow infinities**; no optimized identity shortcut suppresses native 0*infinity NaNs.

PostRotate/PreRotate reject a NaN angle before scratch allocation, perform their corresponding pivot translation, query sine then cosine, write a nine-value rotation and call the corresponding concat operation, then undo pivot translation. SetRotate resets first, including before a later invalid-angle failure. FastMath.Sin/Cos promote the binary32 degree value to binary64, multiply by binary64 pi, divide by 180.0, call the public double sin/cos import and narrow to binary32. Tan first returns +0 for infinite/NaN degrees, otherwise uses the same conversion and double tan import. The PC port uses std::sin/cos/tan instead of reimplementing libm. The exact degree conversion order is retained; final cross-libm ULP agreement remains unverified.

Graphics stores worldMatrix (+0x1f8), local pairs (+0x200), localMatrixIndex (+0x208) and screenMatrix (+0x210). Each local pair has current matrix [0] and accumulated ancestors [1]. PushMatrix increments the int32 index before validation; growth allocates exactly index+1 entries, copies old pair references, fills missing trailing pairs backwards and then publishes the array. A new pair's ancestor matrix is the previous pair's SetConcat, or identity at index zero; SetMatrix copies/reset its current matrix. UpdateScreenMatrix computes ancestor * current, then world * that result. With a negative local index it starts at identity, then world. PopMatrix decrements; an index <=-2 clamps to -1 and emits the debug diagnostic if enabled, then updates screen state. Diagnostic failure leaves the decremented/clamped index and previous screen matrix in place.

BeginRenderMatrix(ref x,ref y) (0x1b5e04c) returns false without effects when local index<0 and local-coordinate count<1. Otherwise it appends reusable flag storage when needed and increments the flag counter before the indexed write. Both coordinates equal zero record a false flag and return true without a world save. Nonzero/NaN coordinates record true, copy world to a reusable saved Matrix, increment the save count, then either call the explicit BeginLocalCoordination service or PreTranslate world by x/y and update screen. Only after success are y and x zeroed. EndRenderMatrix (0x1b73e50) does nothing when save count<1; otherwise decrement the flag counter, and restore/decrement a saved world only for a true flag, followed by the matching local-coordinate service or screen update. A zero-position Begin at save count zero therefore leaves its flag outstanding after End: this native asymmetry is preserved and tested. These are domain state transitions; managed List/array implementation details use standard containers.

The selected preview now binds local push/pop, bitmap Begin/End, affine MapPoints, sprite mirroring, command rotation and skew on an explicitly identity **world** matrix. It also binds the ordinary texture color passes below. Nonzero local-coordinate scopes, world/viewport population, forced materials, atlas population and UI tasks remain explicit/unbound; the full bitmap caller stays partial. It supplies no inferred mission flags or catalog selection. Temporary matrices and their buffers are retained, so repeated supported operations reuse storage.

### Reached color and render-pass contract

This cluster is required by mission command alpha/color packets, including fading physical bullets and tinted enemies. Public SDL 3.4.18 blending and the official [Unity Blend](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-Blend.html) / [BlendOp](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-BlendOp.html) semantics were consulted first. SDL performs blending and rasterization; the port reconstructs KairoLibrary's mode/pass selection, not Unity's shader generator, material caches or runtime containers.

Graphics stores render count/list at +0x140/+0x148, mode/source/destination at +0x150/+0x154/+0x158 and replace at +0x15c. Blend count/list are +0x160/+0x168, mode/packed color +0x170/+0x174 and normalized RGBA +0x178. SetRenderMode accepts raw int32 values without clamping; for mode 1 and wrapping source+destination == 256, decrement destination first. Replace is `(mode==0 && source>254) || (mode==1 && source>254 && destination==0)`. Fields change before the required RenderCache.Reset marks +0x4c dirty. SetBlendMode accepts only unsigned modes 0..3, stores mode/packed color, converts ARGB bytes to binary32 RGBA by division by 255, then invalidates the cache. Mode 2 is RGB modulation, 1 additive color and 3 a separate grayscale-image path.

Push saves into reused three-cell render or two-cell blend rows, increasing the count after all writes; its argument overload then calls the setter. Pop does nothing when wrapping count-1 is negative. Render pop obtains the row and decrements the count before reading cells/setting state; blend pop decrements only after the setter succeeds. These differing failure prefixes are tested rather than replaced with transactional restoration.

RenderPass fields are owner +0x10, private singleton work +0x18, mode/source/destination +0x20/+0x24/+0x28, input colors +0x30, material +0x38, alpha-test override +0x40, restore-blend +0x44, RGB/alpha factors +0x48/+0x4c and output colors +0x50. Regular Init stores owner/mode/source/destination before requiring the colors array, then clears material/restoration and sets alpha-test -1. Empty input uses retained white fallback; one color copies to private singleton work; multiple colors alias the input. Outputs share a cache keyed by color count. Material Init selects mode 0, source 255, destination 0 and factors 255, retaining the explicit material handle. Copy aliases the input/output arrays and state, but keeps the destination's private singleton buffer.

GetRenderPass(Graphics, optional Image, Color[]) allocates reusable arrays of 0..4 passes once. Image alpha kind is -1 when absent; kind 3 becomes -1 for GUI without GL rendering. A forced material returns one material pass. Otherwise a mixed-alpha texture doubles the ordinary pass count, retaining original passes first with alpha-test 1 and shallow copies second with alpha-test 2. Without replace/figure-clip, modes 1/2 select these factors:

| Condition | Mode/source/destination | RGB factor | Alpha factor |
| --- | --- | --- | --- |
| Wrapping source+destination == 255 | Original values, one pass | 255 | source |
| Other sum and destination <=254 | Original mode, 0, destination; first pass | 255 | 255-destination |
| Other sum and source >=1 | Original mode, source, 255; following pass | 255 | source |
| Replace/figure-clip/other mode | -1, 255, 255; one pass | source | 255 |

When both general-sum conditions are absent, the result is an empty array; no placeholder pass is emitted. In particular **mode 0 source 128 dims RGB, keeping opacity; mode 1 source 128/destination 127 scales opacity**. The sum-255 special case still emits one pass when source=0/destination=255.

RenderPass._begin requires owner, asks the host for GUI mode, and if true calls push matrix, load pixel matrix, screen width/height and viewport(0,0,width,height), in that order. A material pass then returns. Other passes push render mode unless mode==-1; source==0/destination<=254 temporarily clears additive blend mode 1 via PushBlendMode(0,0). Begin evaluates A=(input.A*alphaFactor)/255 and RGB=(input.RGB*rgbFactor)/255 with binary32 multiply then divide. Blend mode 2 additionally multiplies each RGB by `(blend.channel*blend.A)`; A is unchanged. End asks GUI mode again and pops its matrix before material early return, render restoration and optional blend restoration. The next pass can overwrite shared output; desktop quad colors are captured before advancing.

Image._getAlphaType's sampled-alpha kernel counts alpha<0.01 as transparent, 0.01<=alpha<=0.999 as partial, and larger values as opaque; unordered values increment neither count. Partial pixels produce kind 2 when no opaque pixel remains, otherwise kind 3. Without partials, any transparent pixel gives kind 1; otherwise retain the previous value, normally 0. The original reads 120x120 texture tiles; the desktop classifies already-decoded RGBA8 pixels. Image alpha overrides, texture liveness, UI-thread readback and deferred classification are not ported.

ShaderBuilder.Init's reached sprite slice normalizes mode 1/source>=255/destination 0 to mode 0, detects texture-only white modulation and adjusts image alpha type using first output alpha and pass override. Its **0.99** shader thresholds differ from the classifier's **0.999**. GetNameId is ported fully: GUI 0x1, shape 0x2/0xa, stencil 0x4, image 0x10, add-color 0x20, texture-only 0x10000; mode-1 families 0x2040/0x4040/0x8040 and mode-2 0x2080/0x4080/0x8080. Opaque kind 0 adds 0x100 outside modes 1/2. GUI returns before alpha-kind 1/2 bits 0x400/0x200 and alpha-test 1/2 bits 0x800/0x1000. Stencil-write/color-mask/depth flags 0x40000/0x20000/0x80000 return early. Special shapes, stencil, add-color and GUI shader keys are explicitly rejected by the selected desktop pipeline.

Supported fixed-function equations use sampled/modulated source C/A and destination D/B (RGB/alpha); results are clamped by the RGBA8 target:

| Pipeline | Output RGB | Output alpha |
| --- | --- | --- |
| Replace | C | A |
| Alpha | C*A + D*(1-A) | A + B*(1-A) |
| Add | C*A + D | A*A + B |
| Subtract-alpha | D - C*A | B*(1-A) - A |
| Subtract-add | D - C*A | B - A*A |
| Attenuate | D*(1-A) | A + B*(1-A) |

Alpha admission uses >0.99 for pass 1, <=0.99 for pass 2, or >=0.01 for cutout without a split override. The SDL adapter prepares retained texture variants with rejected texel alpha zero; this is equivalent to discard for these blending equations, nearest sampling and uniform per-pass alpha. Alpha-test plus replace is rejected. No general shader or CPU rasterizer is added. A separate RGBA8 target texture makes destination alpha explicit; captures read it before copying to the window. The native profile is default, with --raw-rgba retaining the earlier diagnostic copy mode. Forced materials, grayscale, additive-color mode 1, stencil/depth ordering and production render-queue assignment remain unbound.
