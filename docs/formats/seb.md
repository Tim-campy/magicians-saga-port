# SEB sprite / animation

`.seb` files hold groups of sprite records consumed by `kairo.unity.ui.Seb`. The disk layout (modes 0 and 1) is proven by `Seb._load` assembly and by exact consumption + byte-exact rebuild of all 303 shipped files (302 mode 0, 1 mode 1, 452 groups, 2,686 records). C++ implements the disk reader, record normalization/packing, runtime sprite conversion, exact fixed-point interpolation, cache selection and manual frame advance. TexId -> image resolution and presentation remain open.

## Layout

`h` = s16 big-endian, `B` = u8, `I` = u32 big-endian. Sizes 28..2,672 bytes (56,576 total).

| Element | Mode 0 | Mode 1 |
|---|---|---|
| Prefix | none (first byte non-negative) | `ff` (signed -1; other negative values = unknown mode) |
| Header | `group_count:h` (the two bytes read high/low), `header_value:h` = maxFrame | `group_count:h`, `header_value:h` = maxFrame (stored at `this+0x1c`) |
| Group | `record_count:h`, `legacy_value:h` (read at 0x1baf7cc, result unused) | `record_count:h` |
| Record | 10 x `h` -> slots 0..9 (0x1baf918..0x1bafa50) | 4 x `h` -> slots 0,1,6,7; `control:B` -> slot 10; then optional fields |

Mode 1 optional fields, with `d` = second short, `c` = control:

| Field | Present when | Slots | Evidence |
|---|---|---|---|
| `extra_word:I` | -6 <= d <= -2, or (d >= 0 and c != 0) | — | 0x1baf904..0x1bafb20 (negative-d branch taken before the c test; d = -9 never reads it) |
| `pair:2h` | d >= 0 or d = -8 | 2, 3 | 0x1bafb24..0x1bafb70 |
| `tail_pair:2h` | always | 4, 5 | 0x1bafb74..0x1bafbb4 |
| `flags:B` | d >= 0 | bits 0/1 -> 8/9; other bits preserved | 0x1bafbb8..0x1bafbfc |

Endianness proof: `DataInputStream..ctor` (0x1be89e8) wraps a `BinaryReader` stored at `this+0x38`; `DataInputStream.ReadShort` (0x1be8b60) calls `BinaryReader.ReadInt16` (vtable slot 13, method 10009, `ldrh` at 0x1db9548) then `IPAddress.NetworkToHostOrder` (`rev` + shift, 0x2323814..0x232381c). Overload `_load` kairo:0x06001761 only wraps a byte array in `ByteArrayInputStream` and calls kairo:0x06001762.

**Runtime compact buffer** (built by `_load`, 0x1bafc7c..0x1bafdd0, arrays at `this+0x20/+0x28/+0x30`, offsets accumulated 0x1bb00bc..0x1bb01b8): slot 0 (FrameNo) goes to a short array `this+0x28`; other fields packed 8 bytes per record in `this+0x30`: TexId s8, X s8, Y s8, U u8, V u8, W u8, H u8, last byte = Blend (low nibble) | ReverseV (bit 5) | ReverseU (bit 6). TexId byte **-128** marks the extended form: the next byte indexes 7 shorts in `this+0x38` (TexId, X, Y, U, V, W, H), bytes 2..5 form Color (high to low). The final flags byte is shared by both forms. Conversion of a normal compact record **does not write Color**: its destination cell 11 retains the previous value, initially zero in freshly allocated output/scratch arrays.

**Normalization and packing.** `_load` reuses one zero-initialized int32[12] record scratch across all groups. Mode 0 overwrites cells 0..9, resets Blend=0/Color=-1, and for negative TexId derives Blend from `ReverseU & 0xff00`: 0x2000 ->1, 0x4000 ->2, 0x8000 ->3, otherwise zero. Color is `(ReverseU & 0xffff) | ((ReverseV & 0xff)<<16) | alpha`, with alpha 0x80000000 for those three recognized blend selectors, otherwise 0xff000000. Original ReverseU/ReverseV integers are also shifted into the flags byte, not normalized to booleans. Mode 1 overwrites FrameNo/TexId/X/Y/Blend, clears reversals, reads optional Color/U/V and mandatory W/H, and obtains the two reversal bits for nonnegative TexId. **Absent optional Color/U/V retain previous scratch contents**, including across groups. Both modes change Blend 1 to zero when Color's top byte is 255 (0x1bafc2c..0x1bafc50).

An extended entry is required when Blend !=0, TexId is one of -8/-4/-3/-2, TexId/X/Y do not fit s8, or U/V/W/H do not fit u8 (0x1bafdd4..0x1bb004c). The extended index is narrowed to u8 and the seven values to s16; the port preserves those conversions. All group records are then concatenated and first-record offsets accumulated. `prepare_seb_sprites` implements this normalization/packing slice from the existing disk reader; it does not claim the complete loader's bounding-box precomputation or optional extension-block handling.

**Sprite slots** (int32 array, elements from offset 0x20; getters `kairo.unity.ui.Sprite.get_*`): 0 FrameNo, 1 TexId, 2 U, 3 V, 4 W, 5 H, 6 X (= TransX), 7 Y (= TransY), 8 ReverseU, 9 ReverseV, 10 Blend, 11 Color.

**Mirroring** (`ConvBufferToSprite`, 0x1bb2dd0..0x1bb2e80): bit 0 of the reverse argument XOR bit 1 of byte `this+0x40` flips ReverseU and X; bit 0 of `this+0x40` flips vertically. For TexId != -8 and positive size: `X' = -2*floor(W/2) - X`, `Y' = -2*floor(H/2) - Y` (W=5 gives -4). For negative sizes, dimension halving truncates toward zero. The native s16 narrowing applies to the adjusted dimension before the half/negate operations, **not to final X/Y**: W=32767, X=32767 produces X'=-65533. For TexId = -8: negate X, U, W (horizontal) or Y, V, H (vertical). Negative TexIds are commands, never PNG indices.

**Frame selection.** `GetSprite` (0x1bb1900) and `GetSpriteLocal` (0x1bb2290) share the same selection/interpolation body, but obtain different output storage. Both use signed `arg % 10000`, return null for an empty group or a frame outside its first/last keys, and convert exact matches with reverse argument `arg > 9999`. The search narrows by midpoint while frame >=2 and at least three records remain, then scans forward; it preserves the native fallback of two record-zero conversions if a malformed ordering defeats the scan. `GetSpritesLocal` (0x1bb0b90) stores one `GetSpriteLocal` result per group in a reused result list; entries may be null. FrameNo is an internal selection key, not seconds or FPS.

**Between records.** Both neighbours are converted into shared scratch arrays. Let `elapsed = requestedFrame-left.FrameNo` and `span = right.FrameNo-left.FrameNo`. X/Y use `left + trunc(wrap32(trunc(wrap32((right-left)<<12)/span)*elapsed)/4096)`, with truncation toward zero at both divisions. SDIV zero yields zero, and INT32_MIN/-1 yields INT32_MIN. This operation order matters: delta 3, span 9, elapsed 3 gives zero movement, rather than one. FrameNo becomes the normalized request; TexId, reversals, Blend and Color come from the left record. For negative TexId the body additionally computes interpolated U/V/W/H, but **overwrites those four cells with the left record's values** at 0x1bb20dc..0x1bb20f8 / 0x1bb2ad4..0x1bb2af0. Thus the final crop/dimensions are always the left record's. `Seb+0xb0` Flip toggles final ReverseU after evaluation without changing X.

**Work storage and cache.** GetSprite obtains lazy per-instance WorkValue (+0xa8), allocating its output matrix [layer_count][12] once. Local evaluation instead uses explicit per-thread WorkStaticValue storage (+0x10), a table indexed by layer count. If too small it replaces that table with length `layer_count+5`, allocating an i-by-12 matrix for every index i. Its two conversion scratch arrays at +0x30/+0x38 retain their contents across calls and instances. GetSpritesLocal uses another layer-count-indexed table (+0x18), growing to `layer_count+1`. The C++ host supplies this work object directly; runtime thread-static allocation is outside this subsystem.

SetCacheSize (0x1babbfc) replaces Seb+0x48 with `size` age columns, each holding [layer_count][12], and sets every FrameNo cell to -1. A negative size fails before replacement; a zero-length nonnull cache later faults on lookup. Lookup scans columns for that layer, stopping at the first -1 sentinel. A hit moves that **layer's row reference**, rather than the whole column, to the front; a miss moves the last row to the front for reuse, before range validation. The key is normalized frame only: cached frame 0 can satisfy raw frame 10000 without reapplying frame-based reversal. Hits also skip the final Flip toggle. Reverse (0x1babb5c) first invalidates every cached FrameNo and then writes `(horizontal&1)<<1 | (vertical&1)`; direct Flip writes do not invalidate the cache. Returned arrays are shared mutable storage, not immutable sprite snapshots.

**Timing.** Fields: `+0x18` current frame (`GetCurFrame`/`SetCurFrame`, set without normalisation), `+0x1c` max frame (`GetMaxFrame`), static `+0x14` AutoAnimation (setter stores `arg & 1`), `+0xa0` registered flag, `+0xa4` TotalFrames at registration; static `+0x8` collection, `+0x10` active count (static block via GOT 0x272f880, `class+0xb8`).
- `Frame`: returns unchanged if AutoAnimation on or `IApplication.static+0x1c` off (0x1bb1748..0x1bb1778); else `frame = (frame+1) mod maxFrame` via ADD/SDIV/MSUB 32-bit (0x1bb177c..0x1bb178c) with **no guard on maxFrame** (port must define div-by-zero/sign/overflow policy explicitly). Called by `ecs.AnimationSystem.Update`, `RoomForm.Update`, `SubForm.Update` and other forms.
- `PushThisFrameRender`: false if AutoAnimation off or already registered (0x1bb3840..0x1bb3854); if `IApplication.TotalFrames(+0x58) - this+0xa4 >= 2` (signed32) reset frame to 0 (0x1bb38b0..0x1bb38c4); append to collection, growing if needed; count++, set `+0xa0`, store TotalFrames, return true.
- `ThisFrameRenderAnimation`: if AutoAnimation, for each active Seb with maxFrame >= 1, frame = (frame+1) mod maxFrame (guarded). `ResetThisFrameRender`: if AutoAnimation, clear `+0xa0` of each active Seb and zero the count; collection not cleared. `IApplication.OnGUI` calls ThisFrameRenderAnimation at 0x1b84090 (gated by `IApplication.static+0x1c`), then Reset at 0x1b840b0, before main drawing.
- `Draw` overloads (kairo:0x0600178b/8c/8d) call Push, then read `+0x18` and draw regardless of Push's result.
- `Seb..cctor` creates the collection; no explicit AutoAnimation write; no direct BL to the setter found (28 direct BL/B to the five targets scanned).
- Separate per-entity counter: `ecs.AnimationSystem.Update` (0x1141bc0) first calls `Seb.Frame` on its collection, then per entity adds `animation+0x10` to the component counter (`Entity.get_seb` component `+0x18`), calls `RestoreAnimation` when `animation+0x14 != -1` and counter >= maxFrame, then takes the counter mod the earlier maxFrame. Do not merge with the shared Seb frame.

Sample: `load/copy.seb` (28 bytes, one record) = FrameNo 0, TexId 0, U 0, V 0, W 82, H 20, X -41, Y 0; `load/img.inf` ID 0 = `copy.png` (82x20). Naive "TexId = root img.inf ID, U/V/W/H = direct crop": of 2,376 non-negative-TexId records, 46 lack an ID, 47 lack the literal member, 1,515 crops fit, 768 exceed the PNG (OPT remapping, e.g. `hat_com.seb` 30x30 crops vs 39x15 `hat_000.png`). Direct cropping is not a valid renderer rule.

## Reading it

- `tools/inspect_seb.py` (`parse`/`encode`, stdlib): neutral field names (`values`, `header_value`, `legacy_value`, `control`, `extra_word`, `pair`, `tail_pair`, `flags`); rebuild from scalars only; rejects modes other than 0/1, negative counts, truncation, trailing bytes. `tests/test_seb.py` (6). Inventory SHA-256 `70b8d7c9…61d0a0`.
- `src/assets/seb.cpp` (`parse_seb`): `std::optional` for absent fields (JSON `null`), contiguous groups/records; `SebLimits` 32 MiB / 32,767 groups / 1,000,000 records; throws `SebError`. Test `tests/test_seb.cpp`. `asset_inspect --seb` matched `dataclasses.asdict(inspect_seb.parse())` on all 303 files.
- `src/core/gameplay/animation_pass.cpp` implements the shared manual Seb.Frame clock step and the separate ECS entity loop, documented in [animation](../subsystems/animation.md#animationsystemupdate-per-pass). Effective flags are explicit inputs. `animation_resources.cpp` now constructs clocks directly from parsed SEB headers: `_load` calls Dispose at 0x1baf6bc (frame reset at 0x1ba9efc), then reads a signed short at 0x1baf744 and stores it at +0x1c at 0x1baf74c. Both modes share that store. maxFrame is neither the record count nor the largest FrameNo, and no +1 is added. The reader retains the JSON/API name header_value for compatibility. Automatic drawing clocks and the native loader's bounding boxes/extension blocks remain separate.
- `animation_trace` loads a selected SEB, binds its clock to a requested clip slot in the effect resource, creates the actual short-overload effect and advances the live animation group. All 303 manifest-verified files passed a complete period plus two passes through this offline scenario (header maxima 1..101); each yielded effect lifetime maxFrame-1 and matching independent shared/entity counters. Local result: `research/exports/animation-resources/corpus.json`, output SHA-256 `f37b3642583c990c9ef5562a2184640bd78a034767b2ab0765ff067221e1fad3`. This is static-model agreement, not original runtime or pixel verification.
- `src/core/animation/seb_sprite.{hpp,cpp}` implements normalization/packing preparation, ConvBufferToSprite, GetSprite, GetSpriteLocal, GetSpritesLocal, SetCacheSize and Reverse. `tests/test_seb_sprite.cpp` covers compact/extended conversion, stale Color, mode-1 carried fields, odd/negative/extreme dimensions, exact fixed-point truncation, crop overwrite, absent frames, per-layer cache identity/normalized-key quirks and local-versus-instance aliasing. PreparedAnimationResource owns separate sprite states for each selected clip and exposes borrowed payloads beside the separate clocks. `tests/test_render_frame.cpp` binds that payload through the actual RenderSystem command producer.
- `animation_trace ... --sprites` adds evaluated layer arrays to each existing effect/animation trace row. The synthetic disk-file integration test is in `tests/test_animation_scenario.py`. An independent disk-record model matched all **5,863** C++ sprite queries, including **2,391** interpolated queries, across all **303** manifest-hash-verified SEBs over a complete period plus two passes. All queries in this particular corpus scenario were present; synthetic contracts separately cover absent frames. Result: local `research/exports/seb-evaluation/corpus.json`, output SHA-256 `71d98ff01ac373c39fd6430e71284ac1adcf82c47beec1f12c1a5347b3f48c71`. This compares static models, not Android pixels or execution.

## Open questions

1. (blocking) TexId -> Image/OPT resolution and `GetOptimizeSeb`; pixel-consumer semantics of negative TexId commands (-8 and others). Mode-0 colour/control derivation and sprite evaluation are established above.
2. Writers of AutoAnimation and `IApplication.static+0x1c`; real tick rate of `Frame`/`OnGUI`.
3. Semantics of native loader bounding boxes/extension blocks and their GetSpritesLocal warm-up effects on shared scratch; bind native resource-load ordering before production bootstrap. Ignored legacy_value and unused flag bits remain open; extra_word is the Color field when present as specified above.
